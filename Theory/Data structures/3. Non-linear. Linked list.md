# Связный список (Linked list)

**Связный список** — набор **узлов**, разбросанных по памяти; каждый узел хранит значение и **ссылку** на следующий. Первый узел — `head`, последний — `tail`, его ссылка равна `null`.

> Замечание по классификации: связный список — **линейная** структура (элементы идут один за другим), в отличие от деревьев и графов. Нелинейным его иногда называют по признаку «не лежит в памяти подряд», но это про размещение, а не про логическую структуру.

## Зачем он нужен
Массив требует **непрерывного** куска памяти и хранит элементы подряд. Отсюда две проблемы, которые решает связный список:
1. **Нет непрерывного блока** нужного размера — массив создать нельзя, а список соберётся из кусочков.
2. **Вставка и удаление в середину** массива стоят O(n): нужно сдвигать все последующие элементы. В списке достаточно переставить пару ссылок.

Плата — потеря произвольного доступа: чтобы добраться до i-го элемента, придётся пройти по цепочке от головы.

## Виды
- **Односвязный**: узел знает только следующего. Экономнее по памяти, назад ходить нельзя.
- **Двусвязный**: узел хранит ссылки на следующего и предыдущего. Позволяет обход в обе стороны и удаление за O(1), когда узел уже на руках. Именно так устроен `java.util.LinkedList`.
- **Кольцевой**: хвост ссылается на голову; удобен для циклических буферов и round-robin.

```kotlin
class Node<T>(val value: T, var next: Node<T>? = null)

class SinglyLinkedList<T> {
    private var head: Node<T>? = null

    fun addFirst(value: T) {          // O(1)
        head = Node(value, head)
    }

    fun find(value: T): Node<T>? {    // O(n)
        var current = head
        while (current != null) {
            if (current.value == value) return current
            current = current.next
        }
        return null
    }

    fun removeAfter(node: Node<T>) {  // O(1) — узел уже известен
        node.next = node.next?.next
    }
}
```

## Сложность — и главная оговорка
| Операция | Сложность | Уточнение |
| --- | --- | --- |
| Доступ по индексу | **O(n)** | нужно пройти цепочку от головы |
| Поиск значения | **O(n)** | полный перебор |
| Вставка в начало/конец | **O(1)** | у конца — если хранится `tail` |
| Вставка/удаление по ссылке на узел | **O(1)** | переставить ссылки |
| Вставка/удаление по индексу | **O(n)** | O(n) на поиск + O(1) на саму операцию |

Именно последняя строка — самая частая ошибка на собеседовании. Фраза «в связном списке удаление O(1)» верна **только если узел уже найден**. Вызов `list.remove(index)` у `LinkedList` — это всё равно O(n).

## Почему на практике почти всегда выигрывает ArrayList
Асимптотика говорит в пользу списка, а замеры — в пользу массива:
- **Кэш процессора**: элементы `ArrayList` лежат подряд, и чтение одного подтягивает соседей в кэш-линию. Узлы списка разбросаны — почти каждый переход это промах кэша.
- **Память**: каждый узел это отдельный объект со ссылками (в JVM +16–24 байта заголовка на элемент против плотного массива).
- **Сдвиг элементов** в массиве — это `System.arraycopy`, очень быстрая машинная операция.

Вывод: в Android `LinkedList` практически не используют. См. [[ArrayList]], [[LinkedList]], [[Collections. Overview]].

## Где связный список действительно применяется
- **`LinkedHashMap`** — двусвязный список поверх хеш-таблицы, чтобы помнить порядок вставки; на нём строят **LRU-кэш** (`LruCache` в Android).
- **Очереди и деки**: `ArrayDeque`, `LinkedBlockingQueue` — см. [[4. Queue]], [[LinkedBlockingQueue]].
- **Стек вызовов**, списки свободных блоков в аллокаторах, цепочки коллизий в `HashMap` (до превращения в дерево).
- Задачи на собеседованиях: разворот списка, поиск цикла (быстрый и медленный указатели), поиск середины. См. [[- 2 Fast and Slow Pointers]], [[6 In-place Linked List Reversal]].

## Вопросы-ловушки
- Почему говорят, что удаление в списке O(1), а `list.remove(5)` работает за O(n)? → O(1) — это переставить ссылки; поиск нужного узла всё равно линейный.
- Что быстрее на практике при вставке в середину — `ArrayList` или `LinkedList`? → обычно `ArrayList`: копирование памяти дешевле, чем цепочка промахов кэша.
- Зачем двусвязный список, если односвязный экономнее? → обход назад и удаление известного узла за O(1) без ссылки на предыдущий.
- Как найти цикл в списке? → два указателя, быстрый идёт на два шага, медленный на один: если встретились — цикл есть.
- Как найти середину за один проход? → тем же приёмом: когда быстрый дошёл до конца, медленный ровно посередине.
