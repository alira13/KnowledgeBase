# Бинарное дерево поиска (BST)

**Бинарное дерево** — структура, где у каждого узла не более двух потомков: левый и правый.

**Бинарное дерево поиска (Binary Search Tree)** добавляет к этому одно правило, которое и делает его полезным:

> в левом поддереве — только ключи **меньше** ключа узла, в правом — только **больше**.

Правило выполняется рекурсивно для каждого узла, а не только для корня. Ключи считаются уникальными.

## Зачем это нужно
Правило даёт возможность на каждом шаге **отбрасывать половину** оставшихся узлов — как в бинарном поиске по отсортированному массиву. Разница в том, что массив нужно держать отсортированным (вставка O(n)), а дерево позволяет и искать, и вставлять за O(log n).

```
        8
      /   \
     3     10
    / \      \
   1   6      14
      / \    /
     4   7  13
```
Ищем 6: 6 < 8 → налево; 6 > 3 → направо; нашли. Три сравнения вместо перебора.

## Операции
```kotlin
class Node(val key: Int, var left: Node? = null, var right: Node? = null)

fun search(node: Node?, key: Int): Node? = when {
    node == null || node.key == key -> node
    key < node.key -> search(node.left, key)
    else -> search(node.right, key)
}

fun insert(node: Node?, key: Int): Node = when {
    node == null -> Node(key)                                    // дошли до пустого места
    key < node.key -> node.also { it.left = insert(it.left, key) }
    key > node.key -> node.also { it.right = insert(it.right, key) }
    else -> node                                                  // дубликат — игнорируем
}
```

**Удаление** разбирают на собеседовании чаще всего — три случая:
1. **Лист** — просто убрать.
2. **Один потомок** — подставить потомка на место удаляемого.
3. **Два потомка** — заменить узел его **преемником** (самый левый узел правого поддерева) или предшественником, затем удалить преемника из его старого места. Только так сохраняется правило порядка.

## Обходы
| Обход | Порядок | Что даёт |
| --- | --- | --- |
| **in-order** (симметричный) | левый → узел → правый | **отсортированная** последовательность ключей |
| **pre-order** (прямой) | узел → левый → правый | копирование/сериализация дерева |
| **post-order** (обратный) | левый → правый → узел | удаление дерева, вычисление выражений |
| **BFS** (по уровням) | очередь | поиск кратчайшего пути, печать по слоям |

Свойство in-order — частый вопрос: если обойти BST симметрично, получишь ключи по возрастанию.

## Сложность и главная проблема
| Операция | Средний случай | Худший случай |
| --- | --- | --- |
| Поиск | O(log n) | **O(n)** |
| Вставка | O(log n) | **O(n)** |
| Удаление | O(log n) | **O(n)** |

Сложность равна **высоте** дерева. Если вставлять уже отсортированные данные (1, 2, 3, 4, 5), каждый новый ключ уходит вправо, и дерево **вырождается в связный список** высотой n — вся выгода теряется.

```
1
 \
  2
   \
    3
     \
      4
```
Это и есть причина, по которой в реальных библиотеках используют не голый BST, а **самобалансирующиеся** деревья, которые после каждой вставки восстанавливают высоту порядка log n:
- [[Trees. Balanced. AVL]] — строгий баланс, быстрый поиск, дороже вставка;
- [[Trees. Balanced. Red-black]] — слабее баланс, дешевле перестройка; на нём построены `TreeMap`, `TreeSet` и бакеты `HashMap` после treeification;
- [[Trees. Treap]], [[Trees. Balanced. Splay]] — вероятностный и самонастраивающийся варианты;
- [[Trees. B-tree]] — для дисков и БД: широкие узлы под размер страницы.

## Где встречается
- `TreeMap` / `TreeSet` в Java и Kotlin — отсортированный доступ за O(log n). См. [[Collections. Overview]].
- Бакеты `HashMap` превращаются в красно-чёрное дерево при 8+ коллизиях.
- Индексы в базах данных (обычно B-дерево или B+).
- Автодополнение, диапазонные запросы «все ключи от A до B».

## Когда BST лучше хеш-таблицы
`HashMap` даёт O(1) против O(log n) — но **не умеет порядок**. Дерево выбирают, когда нужны: отсортированный обход, поиск ближайшего значения (`floorKey`/`ceilingKey`), диапазонные запросы, предсказуемая сложность без деградации на плохих хешах.

## Вопросы-ловушки
- Всегда ли поиск в BST O(log n)? → нет, только при сбалансированном дереве; в вырожденном — O(n).
- Что произойдёт, если вставлять отсортированный массив? → дерево выродится в список.
- Как получить отсортированный список ключей? → in-order обход.
- Как удалить узел с двумя потомками? → заменить преемником (минимум правого поддерева).
- Чем BST лучше `HashMap`? → упорядоченностью: сортированный обход и диапазонные запросы.
