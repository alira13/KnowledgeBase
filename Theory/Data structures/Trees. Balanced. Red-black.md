# Красно-чёрное дерево (Red-Black tree)

Самобалансирующееся [[Trees. Binary search tree|бинарное дерево поиска]], где каждый узел окрашен в **красный** или **чёрный**. Баланс поддерживается не строго, но достаточно для гарантии высоты **O(log n)**.

## Свойства (инварианты)
1. Каждый узел красный или чёрный.
2. Корень чёрный.
3. Все листья (NIL) чёрные.
4. У красного узла оба потомка чёрные (нет двух красных подряд).
5. На любом пути от узла до листьев одинаковое число чёрных узлов (**black-height**).

Из этих правил следует: самый длинный путь ≤ 2× самого короткого → дерево «примерно» сбалансировано.

## Балансировка
После вставки/удаления баланс восстанавливают **перекрашиванием** и **поворотами** (левый/правый). Модификаций обычно меньше, чем в AVL.

## Сложности — все O(log n)
Поиск, вставка, удаление.

## Где применяется (важно!)
- **`TreeMap` / `TreeSet`** в Java/Kotlin — реализованы на красно-чёрном дереве (отсортированный порядок ключей).
- **`HashMap`** в Java 8+ — при коллизиях длинная цепочка в бакете превращается в красно-чёрное дерево (при ≥8 элементов), чтобы деградация была O(log n), а не O(n). Частый вопрос на собесе!

## RB vs AVL
- RB — быстрее вставка/удаление, чуть медленнее поиск → для часто изменяемых структур (стандартные библиотеки).
- AVL — строже баланс, быстрее поиск. См. [[Trees. Balanced. AVL]].
