# B-дерево (B-tree)

Сбалансированное **сильно ветвящееся** дерево поиска: у узла много ключей и много потомков (не 2, как в BST). Все листья на одном уровне. Оптимизировано для хранилищ с блочным доступом (диск, БД).

## Идея
- Узел содержит до `2t−1` ключей и до `2t` потомков (`t` — минимальная степень).
- Ключи в узле отсортированы; потомки разбивают диапазоны между ключами.
- Высота очень мала за счёт большого ветвления → мало обращений к диску.

## Зачем такое ветвление
Чтение с диска/SSD идёт **блоками**. Один узел B-дерева ≈ один блок. Большое число ключей в узле = меньше уровней = меньше дорогих операций I/O. Для этого и придумано: минимизировать обращения к диску, а не к памяти.

## Сложности — O(log n)
Поиск, вставка, удаление. База логарифма большая (ветвление), поэтому дерево «плоское».

## B-tree vs B+-tree
- **B-tree** — данные хранятся во всех узлах.
- **B+-tree** — данные только в листьях, листья связаны в список → быстрый диапазонный обход. Используется в индексах реляционных БД и файловых системах.

## Где применяется
- **Индексы БД** (PostgreSQL, MySQL InnoDB — B+-tree), в т.ч. под капотом **SQLite/Room** на Android.
- Файловые системы (NTFS, ext4).
