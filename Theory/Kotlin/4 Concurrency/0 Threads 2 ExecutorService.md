Проблемы работы с потоками
  - создание thread занимает немало времени 
  - создание thread занимает немало оперативной памяти. Когда потоков много, может случиться ex OutOfMemError
  -  управление жизненным циклом потоков, например их отмена. Когда нужно что-то с потоками сделать, например отменить,  их нужно сохранить в переменную в список и затем проходиться по ним.  Управление жизненным циклом потока становится сложным 
  
```kotlin
fun main() {  
    repeat(10_000) {  
        thread {  
            workWithImage(Image(it))  
        }  
    }  
}  
  
data class Image(val id: Int)  
  
private fun workWithImage(image: Image) {  
    println("Working with $image")  
    Thread.sleep(1000)  
    println("Done")  
}
```



`ExecutorService` — это API в Java (и Kotlin), который создает, управляет **потоками** и позволяет **асинхронно** выполнять задачи в пуле потоков (**Thread Pool**).
Оперирует:
 - очередь потоков
 - пул потоков

При создании ES создается определенное количество потоков, например 5
И все эти потоки ожидают задач. Если мы хотим, чтобы какая-то задача была создана, мы не создаем сами поток, а отдаем ее ES и если свободные потоки есть, то один из них берет задачу в работу, появилась еще-еще. Если же все потоки заняты, то задача становится в очередь и как только какой-то поток освободился, задача из очереди попадает ему на выполнение.(как в МФЦ)

В процессоре 2 ядра. Если создать 2 потока, то каждый будет выполняться на своем ядре. Но если потока 4, то на ядрах эти потоки будут постоянно переключаться(на что требуется время) и нам будет казаться, что задачи выполняются паралелльно -ПСЕВДОПАРАЛЛЕЛИЗМ. То есть если сложные вычисления, то количество потоков=количеству ядер, чтобы не переключаться.
## **1. Типы `ExecutorService`**

В `Executors` есть несколько вариантов пулов потоков:

| Метод                                 | Описание                                                                                                                                                                                                                         | Когда использовать?                                                                                                                                                                                                                                               |
| ------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Executors.newFixedThreadPool(n)`     | Создается фиксированное число потоков (`n`). И работают как в описании выше                                                                                                                                                      | Для сложных вычислений, когда количество потоков равно количеству ядер, чтобы избежать излишних переключений между потоками<br>                                                                                                                                   |
| `Executors.newSingleThreadExecutor()` | Только 1 поток (очередь задач). То есть при одном потоке все задачи становятся в очередь и по порядку выполняются. По сути задачи выполняются последовательно друг за другом                                                     | Только 1 поток может отрисовывать UI. Работа с UI разрешена только из Main потока. Иначе несколько потоков будут пытаться изменить UI и будет непредсказуемая работа.<br>Когда задачи должны выполняться В ФОНЕ, не в главном потоке, но при этом последовательно |
| `Executors.newCachedThreadPool()`     | Динамически создаёт новые потоки при необходимости. Если все потоки заняты, создастся новый, иначе работа задач идет на свободных потоках(надо быть осторожным, иначе воздникнет проблема как и без сервиса и память закончится) | Для операций чтения и записи(из интернета), но лучше ограничить максимальное число потоков. Обычно 64                                                                                                                                                             |
| `Executors.newScheduledThreadPool(n)` | Позволяет выполнять задачи с задержкой или периодически.                                                                                                                                                                         |                                                                                                                                                                                                                                                                   |


🔹 **Основные функции `ExecutorService`:**  
✅ Управляет потоком выполнения (создание, запуск, завершение).  
✅ Позволяет **переиспользовать потоки** (Thread Pool), снижая накладные расходы.  
✅ Позволяет запускать **асинхронные** задачи (`Callable`, `Runnable`).  
✅ Позволяет получать **результаты выполнения** (`Future`).

---

## **1. Создание `ExecutorService`**

Ты можешь создать `ExecutorService` через `Executors`:

```kotlin
val executor: ExecutorService = Executors.newFixedThreadPool(3)
```

Этот пул создаст **до 3 потоков**, которые будут переиспользоваться.

---

## **2. Запуск задач (`execute` vs `submit`)**

Запуск задач можно сделать двумя способами:

### ✅ **`execute(Runnable)` — без возврата результата**

Используется для **задач без возврата результата**.

```kotlin
executor.execute {
    println("Задача выполняется в потоке: ${Thread.currentThread().name}")
}
```

### ✅ **`submit(Callable)` — с возвратом результата (`Future`)**

Если задача должна вернуть результат, используй `submit()`, который возвращает `Future<T>`.

```kotlin
val future: Future<String> = executor.submit(Callable {
    Thread.sleep(1000) // Имитация долгой задачи
    "Результат выполнения"
})
println(future.get()) // get() блокирует поток, пока результат не будет готов
```

📌 `get()` **блокирует текущий поток**, пока результат не будет готов.

---


## **4. Завершение `ExecutorService`**

После работы **нужно завершать** `ExecutorService`, иначе приложение **не остановится**!

```kotlin
executor.shutdown() // Ждёт завершения всех задач
// executor.shutdownNow() // Принудительное завершение всех задач
```

---

## **5. Пример: Несколько параллельных задач**

```kotlin
val executor = Executors.newFixedThreadPool(3)

val task1 = executor.submit(Callable {
    Thread.sleep(1000)
    "Task 1 Completed"
})

val task2 = executor.submit(Callable {
    Thread.sleep(500)
    "Task 2 Completed"
})

println(task1.get()) // "Task 1 Completed"
println(task2.get()) // "Task 2 Completed"

executor.shutdown()
```


🔹 `ExecutorService` — это **менеджер потоков**, который управляет асинхронными задачами.  
🔹 Позволяет **оптимизировать** работу потоков, переиспользуя их.  
🔹 Используется **для многопоточных задач**, требующих **управления временем выполнения**.
🔹 Всегда **вызывай `shutdown()`**, чтобы остановить пул потоков!
