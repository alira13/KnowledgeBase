Rx-Java

В библиотеке RxJava вводится специальный объект — `Observable`. Это объект, за которым можно **наблюдать** и на чьи действия можно **реагировать**. По сути, это источник потока данных или его уже преобразованная часть. Объект, который наблюдает и реагирует на `Observable`, называется **наблюдателем** или `**Observer**`.  
  
  
**Rx-цепочка**

```Kotlin
getObservable()
        .filter { it.flag && it.value > 20 }
        .map { model -> convertModelToAnother(model) }
        .subscribe(
                {
                /* Do something with model */
                }
        )
```

Основана на fluent-интерфейсе

Fluent interface — это способ написания программ, который упрощает вызов множества функций подряд, работающих с одним и тем же объектом (как в случае с `Retrofit.Builder()`) или с одним и тем же контекстом выполнения

Всё начинается с метода, который создаёт объект или контекст, а затем этот объект каскадно (последовательно, сверху вниз) передаётся в каждую последующую функцию. Такой способ написания кода ещё часто называют цепочкой вызовов — **method chaining**.

  

- RxJava — это реализация [реактивной спецификации (Reactive Extensions)](https://reactivex.io/) для использования в JVM. Спецификация описывает API для удобной работы с потоками данных и асинхронным кодом.

_**ReactiveX**_ — _**это**_ проект который содержит имплементацию реактивного програмирования для разных языков.

Reactive Extensions определяют специальные контракты между источниками данных и наблюдателями, то есть интерфейс взаимодействия между разными сущностями.

Наблюдателей у одного `Observable` может быть сколько угодно. Все наблюдатели будут получать одинаковые последовательности событий от источника данных, без каких-либо изменений.  
Библиотека RxJava построена на использовании  
[паттерна проектирования «Наблюдатель»](https://refactoring.guru/ru/design-patterns/observer), который вводит понятия «Наблюдаемого объекта» (`Observable`) и «Наблюдателя» (`Observer`).

- `Observable` представляет собой источник данных, на который можно подписаться и реагировать.
- Rx-цепочка представляет собой последовательность вызовов **операторов RxJava**, которые могут создавать источники данных, модифицировать, фильтровать и так далее. Данные в цепочке движутся сверху вниз, поэтому порядок вызова операторов важен.

  

Rx-Kotlin

Так как RxJava — это библиотека, которая предназначена для **любых JVM-приложений**, в ней нет понятия «главный поток», потому что для разных устройств (декстоп, мобильные телефоны) «главный поток» будет обозначать разные вещи.

Для Android-приложений написана маленькая [библиотека RxAndroid](https://github.com/ReactiveX/RxAndroid/tree/2.x), которая предоставляет два дополнительных `Scheduler`:

- `AndroidSchedulers.mainThread()` — это `Scheduler`, который переключает код на UI-поток.
- `AndroidSchedulers.from(Looper)` — `Scheduler`, который выполняет код на указанном `Looper`.

Когда к Android-проекту подключают библиотеку RxJava, обычно подключают и RxAndroid.

Один из самых популярных вопросов на собеседованиях по RxJava: «По каким принципам стоит выбрать `Scheduler` для решения задачи?»  
Чаще всего в приложениях вы будете использовать всего три  
`Scheduler`: `Schedulers.io()`, `Schedulers.computation()`, `AndroidSchedulers.mainThread()`.

Стоит запомнить, для чего именно нужны эти `Scheduler` и разницу между ними.

  

  

Применение RX-Java в многопоточности

В Android-приложениях часто приходится манипулировать потоками. Например, в Android-приложениях запрещено выполнять сетевые запросы на UI-потоке, поэтому приходится выносить тяжёлую работу на background-потоки, а затем возвращать результаты на главный поток, чтобы модифицировать UI-элементы экрана.

Известное вам переключение между потоками с помощью `Handler` и `Looper` нельзя назвать удобным. Приходится писать много кода, обычно основанного на колбэках, что может привести к Callback Hell.  
  
  
`Scheduler` («шедулер», англ. «планировщик») - абстракция RX-Java, которая переключает обработку элементов Rx-цепочки на нужные потоки (`Thread`)

Библиотека RxJava предоставляет несколько готовых `Scheduler`, которые можно создать с помощью класса-фабрики — `Schedulers`:

- `Schedulers.io()` используется для выполнения операций ввода-вывода (input/output, или сокращённо IO) — загрузки файлов, запросов в сеть и работы с базами данных. Этот планировщик имеет неограниченное число потоков и автоматически увеличивает или уменьшает число потоков в зависимости от нагрузки.
- `Schedulers.computation()` используется для выполнения вычислительно сложных операций — математических вычислений и обработки данных. Этот планировщик имеет фиксированное число потоков, которое зависит от числа доступных процессоров на устройстве.
- `Schedulers.newThread()` используется для выполнения операций в новом потоке. Каждый раз, когда операция отправляется на этот планировщик, создаётся новый поток, который выполняет задачу.
- `Schedulers.single()` используется для выполнения операций в единственном потоке последовательно. Этот планировщик создаёт один поток, который выполняет все операции по очереди.
- `Schedulers.trampoline()` используется для выполнения операций в текущем потоке. Он может быть полезен для тестирования и отладки кода.
