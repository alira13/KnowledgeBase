### **Coroutine Builder в Kotlin**

**Coroutine Builders** (строители корутин) — это функции, которые создают и запускают корутины. Они определяют, **как** и **где** будет выполняться корутина, а также ее жизненный цикл.

Число корутин=числу билдеров в коде(кроме withContext, он не создает корутину )
---

## 🔹 **Основные coroutine builders в Kotlin**

| Coroutine Builder  | Возвращает                              | Блокирует поток? | Когда использовать?                                                                                                                                                                                            | Работа с ожиданием                                              |
| ------------------ | --------------------------------------- | ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| `launch`           | `Job` - это корутина                    | ❌ Нет            | Для задач, которые не возвращают никаких данных. Когда мы хотим работать только с самой корутиной, отменять ее, ждать и тд, но сами данные, находяшиеся внутри корутины для дальнейшей обработки нам не нужны. | `join(joinAll)` ожидает окончания корутины                      |
| `async`            | `Deferred<T>` реализует интерфейс `Job` | ❌ Нет            | Для задач, которые возвращают результат                                                                                                                                                                        | `async` ожидает окончание корутины и возвращает данные типа `T` |
| `runBlocking`      | `Unit`                                  | ✅ Да             | Для тестов или entry point                                                                                                                                                                                     |                                                                 |
| `withContext`      | `T`                                     | ❌ Нет            | Для смены контекста без создания новой корутины                                                                                                                                                                |                                                                 |
| launch(newContext) |                                         |                  | Для смены контекста без создания новой корутины                                                                                                                                                                |                                                                 |

## ✅ **1. `launch` – Запуск корутины без результата**

Используется, когда **не нужно возвращать данные**, например, для фоновых задач.

```kotlin
fun main() = runBlocking {
    launch { 
        delay(1000)
        println("Hello from launch!") 
    }
    println("This prints first") // Выполнится раньше
}
```

📌 **Возвращает**: `Job` - по сути это корутина, который можно использовать для отмены или ожидания окончания корутины или корутин


```kotlin
val job = launch {
    delay(1000)
    println("Done")
}
job.cancel() // Отмена корутины
```

---

## ✅ **2. `async` – Запуск корутины с возвращаемым значением**

Используется, когда **нужно вернуть результат**. Работает как `launch`, но возвращает `Deferred<T>`.

```kotlin
val deferred: Deferred<Int> = async {
    delay(1000)
    42
}

val result = deferred.await() // Дождёмся результата
println(result) // 42
```

📌 **`await()` блокирует только внутри корутины** и ждёт завершения задачи.

---

## ✅ **3. `runBlocking` – Блокирует поток (не рекомендуется в продакшене)**

Используется **только для тестов или в `main()`**, так как **блокирует текущий поток**.

```kotlin
fun main() = runBlocking {
    launch {
        delay(1000)
        println("Hello")
    }
    println("Blocking main thread") // Ожидает завершения всех корутин
}
```

📌 **Лучше не использовать в Android-приложениях!**

---

## ✅ **4. `withContext` – Переключение контекста без создания новой корутины**

В отличие от `launch` и `async`, **не создаёт новую корутину**, а просто выполняет код в другом `Dispatcher`.

```kotlin
val result = withContext(Dispatchers.IO) {
    delay(1000)
    "Data loaded"
}
println(result) // Data loaded
```

📌 **Когда использовать?**  
✔ Для смены контекста (например, `IO` → `Main`).  
✔ Когда нужен **результат**, но без создания новой корутины.

---

## 🔹 **Когда использовать?**

- **Используйте `launch`**, если **не нужно** возвращать результат (например, логирование, обновление UI).
- **Используйте `async`**, если **нужно** вернуть результат (например, сетевой запрос).
- **Используйте `runBlocking`**, **только если** нужно заблокировать поток (например, в `main()` или тестах).
- **Используйте `withContext`**, если просто нужно **переключить контекст**, не создавая новую корутину.
