
Отмена корутин в Kotlin является кооперативным процессом, то есть корутина должна сама проверять, не была ли она отменена. Обработка флага лежит на совести создателя suspend-функции внутри этой корутины.

Условия полной отмены корутины:
 - Корутина переведена в статус isActive=false
 - Внутри корутины должен быть какой-то источник `CancellationException` (сообщает scope об отмене при `IsActive=false`): либо библиотечная функция, либо наш кастомный код (например в цикле while должно быть такое условие)
 - Должны быть механизмы пропуска `CancellationException` к корневой корутине(проблема блока Try-catch: нужно быть внимательным при оборачивании кода try-catch, чтобы он смог пропустить CancellationException).

CancellationException  - это особое исключение для отмены корутин. Не нужно обрабатывать в ExceptionHandler.

### Процесс отмены корутины

1. **Отмена корутины**: Когда вызывается метод `cancel()` на объекте `Job`, корутина переходит в состояние **Cancelling**. Это означает, что корутина больше не будет выполняться, но она еще не завершила все свои действия[1](https://tech-geek.ru/cancellation-in-kotlin-coroutines/)[2](https://habr.com/ru/articles/873076/). Выставляется флаг `IsActive=false` .То есть метод cancel не отменяет корутину, а лишь выставляет флаг.
2. **Обработка отмены**: В состоянии **Cancelling** корутина проверяет все точки остановки (например, вызовы suspend-функций) и выбрасывает исключение `CancellationException`, если корутина была отменена[6](https://kotlinlang.org/docs/cancellation-and-timeouts.html). 
	Источники `CancellationException`
		библиотечные функции внутри корутины В библиотеке корутин Kotlin есть несколько встроенных функций, которые проверяют статус `isActive` корутины. Хотя эти функции не проверяют `isActive` напрямую, они отменяемые и проверяют статус корутины, выбрасывая `CancellationException` при отмене. Вот некоторые из этих функций:
			1. **`delay()`**: Эта функция приостанавливает корутину на определенное время и проверяет статус корутины. Если корутина была отменена, она выбрасывает `CancellationException`
			2. **`yield()`**: Хотя `yield()` не проверяет напрямую `isActive`, она может быть использована для того, чтобы корутина стала отменяемой, позволяя ей периодически проверять статус.
			3. **`withTimeout()`**: Эта функция устанавливает тайм-аут для корутины. Если корутина не завершила свою работу в течение указанного времени, она отменяется и выбрасывает `TimeoutCancellationException`.
			4. **`await()`**: Эта функция ожидает завершения корутины или задачи и проверяет статус корутины. Если корутина была отменена, она выбрасывает `CancellationException`.
			5. **`trySend()` и `tryReceive()`**: Эти функции не останавливают корутину, но могут быть использованы в контексте, где корутина может быть отменена. Однако они не проверяют напрямую `isActive`.
		сами генерим CancellationException
		1. **Циклы**: В циклах можно проверять `isActive`, чтобы остановить выполнение корутины, если она была отменена.   `while (isActive) {// Код корутины }`
		2. **Функция `ensureActive()`**: Эта функция выбрасывает исключение `CancellationException`, если корутина не активна. Она может быть использована внутри корутины для проверки статуса.
		3. **Ручная проверка**: Можно вручную проверять статус корутины с помощью `isActive` и выбрасывать исключение или завершать работу корутины. `if (!isActive) {     throw CancellationException() }`
		4. **Функция `yield()`**: Хотя `yield()` не проверяет напрямую `isActive`, она может быть использована для того, чтобы корутина стала отменяемой, позволяя ей периодически проверять статус.

3. **Завершение ресурсов**: В блоке `finally` корутина может освободить ресурсы и выполнить любые необходимые действия перед завершением[1](https://tech-geek.ru/cancellation-in-kotlin-coroutines/).
4. **Переход в Completed**: После того, как корутина обработала исключение отмены и завершила все необходимые действия, она переходит в состояние **Completed**. Это означает, что корутина полностью завершила свою работу, либо нормально, либо с ошибкой[4](https://habr.com/ru/companies/deliveryclub/articles/663392/).
5. **Уведомление родителя**: Если корутина имеет родителя, она уведомляет его о своем завершении. Если все дочерние корутины завершили свою работу, родительская корутина также переходит в состояние **Completed**[4](https://habr.com/ru/companies/deliveryclub/articles/663392/).

Этот процесс гарантирует, что корутины завершаются правильно и освобождают ресурсы, даже если они были отменены.

```kotlin
import kotlinx.coroutines.*

suspend fun main() = coroutineScope {
    val downloader: Job = launch {
        try {
            println("Начинаем загрузку файлов")
            for (i in 1..5) {
                println("Загружен файл $i")
                delay(500L)
            }
        } catch (e: CancellationException) {
            println("Загрузка файлов прервана")
        } finally {
            println("Загрузка завершена")
        }
    }
    
    delay(800L)
    println("Надоело ждать. Прерву-ка я загрузку...")
    downloader.cancelAndJoin() // отменяем корутину и ждем ее завершения
    println("Работа программы завершена")
}
```

| **Вид отмены**           | **Описание**                                                                                                     | **Случаи применения**                                                                        |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| **Штатная отмена**       | Отмена корутины с помощью `cancel()` или `cancelAndJoin()`. Все дочерние корутины также отменяются.              | Когда необходимо отменить корутину из-за изменения условий или завершения работы приложения. |
| **Внештатная отмена**    | Отмена корутины из-за ошибки или исключения. Если используется `SupervisorJob`, дочерние корутины не отменяются. | Когда возникает ошибка в одной из корутин и необходимо продолжить выполнение других.         |
| **Кооперативная отмена** | Корутина должна сама проверять статус отмены и завершать работу.                                                 | Для корутин, которые выполняют вычисления и не используют suspend-функции.                   |
| **Отмена по тайм-ауту**  | Отмена корутины по истечении определенного времени с помощью `withTimeout()`.                                    | Когда необходимо ограничить время выполнения корутины.                                       |

Эта таблица помогает понять основные виды отмен корутин и ситуации, в которых они применяются.


## Использование NonCancellable
**NonCancellable** в контексте корутин Kotlin — это специальный контекст, который позволяет выполнять код без прерывания даже если корутина была отменена. Этот контекст используется с функцией `withContext(NonCancellable)`, чтобы гарантировать, что определенный блок кода будет выполнен полностью, не будучи прерванным отменой корутины.

`NonCancellable` обычно используется в блоках `finally`, чтобы гарантировать, что ресурсы будут освобождены, даже если корутина была отменена. Это особенно важно для операций, которые не должны быть прерваны, таких как закрытие файлов или сетевых соединений.
