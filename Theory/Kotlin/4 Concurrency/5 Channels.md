Для взаимоствязи данных из разных корутин. Каждая корутина может класть в канал данные и каждая может взять данные.
Бывают корутины
 - отправляют данные channel.send
 - потребители - получают данные 
	 - channel.consumeAsFlow() - поддерживает одного подписчика и не может retry. Так как retry заново создает нового подписчика
	 - receiveAsFlow - поддерживает много подписчиков и соответсвенно retry

Каналы были придуманы до горячих flow. Сейчас можно заменить на горячие flow


### 🔹 **Сравнение `Channel` и `SharedFlow` в Kotlin**

`Channel` и `SharedFlow` – это механизмы передачи данных между корутинами, но они работают по-разному. Давайте разберемся, когда какой лучше использовать.

---

## **1. `Channel` – механизм для одноразовой передачи сообщений**

🔹 `Channel` – это аналог очереди (FIFO), где **каждое сообщение потребляется только одним получателем**.  
🔹 По умолчанию канал **закрывается**, когда отправитель завершает свою работу.

📌 **Пример `Channel`**:

```kotlin
import kotlinx.coroutines.*
import kotlinx.coroutines.channels.Channel

fun main() = runBlocking {
    val channel = Channel<Int>()

    launch {
        for (i in 1..5) {
            channel.send(i)
            println("Sent: $i")
        }
        channel.close() // Обязательно закрываем канал
    }

    launch {
        for (msg in channel) {
            println("Received: $msg")
        }
    }
}
```

🔹 **Вывод:**

```
Sent: 1  
Received: 1  
Sent: 2  
Received: 2  
...  
```

✅ **Каждое сообщение передается и обрабатывается единожды одним получателем.**  
❌ **Если нет активных получателей, отправка приостановится (по умолчанию, `Channel.UNLIMITED` можно изменить).**

---

## **2. `SharedFlow` – механизм для многократной передачи сообщений**

🔹 `SharedFlow` – это поток, который **рассылает данные всем подписчикам**.  
🔹 В отличие от `Channel`, поток **никогда не закрывается автоматически**.

📌 **Пример `SharedFlow`**:

```kotlin
import kotlinx.coroutines.*
import kotlinx.coroutines.flow.MutableSharedFlow

fun main() = runBlocking {
    val sharedFlow = MutableSharedFlow<Int>()

    launch {
        sharedFlow.collect { println("Collector 1 received: $it") }
    }

    launch {
        sharedFlow.collect { println("Collector 2 received: $it") }
    }

    launch {
        for (i in 1..3) {
            sharedFlow.emit(i)
            delay(100) // Даем время потребителям обработать данные
        }
    }

    delay(500) // Ждем завершения всех операций
}
```

🔹 **Вывод:**

```
Collector 1 received: 1  
Collector 2 received: 1  
Collector 1 received: 2  
Collector 2 received: 2  
...  
```

✅ **Один элемент передается сразу нескольким подписчикам.**  
❌ **Если подписчиков нет, данные теряются (по умолчанию, но можно настроить `replay`).**

---

## **🔍 Сравнительная таблица**

|Характеристика|`Channel`|`SharedFlow`|
|---|---|---|
|**Тип передачи**|Point-to-Point (один отправитель – один получатель)|Broadcast (один отправитель – много подписчиков)|
|**Буферизация**|Можно настроить (`Channel.UNLIMITED`, `Channel.BUFFERED`, `Channel.CONFLATED`)|Можно настраивать через `replay` и `extraBufferCapacity`|
|**Закрытие**|Необходимо явно вызывать `close()`|Поток не закрывается сам|
|**Повторная подписка**|Новые подписчики получают **только новые данные**|Можно настроить `replay`, чтобы новые подписчики получали предыдущие данные|
|**Когда использовать?**|Для одноразовой передачи данных|Для многократного использования (события, обновления)|

---

## **📌 Когда использовать что?**

|Ситуация|Что лучше?|Почему?|
|---|---|---|
|Нужно передать сообщение строго **одному** получателю|`Channel`|Сообщение забирает только один потребитель|
|Нужно, чтобы **несколько** подписчиков получали данные|`SharedFlow`|Все подписчики получат одно и то же сообщение|
|Данные должны **копиться для новых подписчиков**|`SharedFlow(replay = N)`|Новые подписчики получат `N` предыдущих сообщений|
|Корутинный поток событий (например, клики)|`SharedFlow`|Работает без закрытия и поддерживает `replay`|

---

## **📌 Итог**

- Используйте `Channel`, если **данные должны обрабатываться только одним потребителем**.
- Используйте `SharedFlow`, если **нужно рассылает данные сразу нескольким подписчикам** (например, события в UI).
