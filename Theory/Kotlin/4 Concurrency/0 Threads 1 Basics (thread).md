**Многопоточность** - способность выполнять действия одновременно
Пример:
	У нас есть 1 секретарь, который может выполнять задачи последовательно - это один поток. 
	Если мы добавим второго секретаря - это будет второй поток, который может также выполнять последовательно задачи. Вместе они будут работать независимо и параллельно

Первоначально у нас есть только один поток MAIN, в котором по умолчанию запускаются все действия.

### Способы создания потоков
##### Простейший в Java через объект Thread
1) Создать объект типа Thread и передать ему в конструктор реализацию интерфейса Runnable (интерфейс, у которого есть только 1 метод run(функциональный)) и переопределить этот метод, в котором запустить действие, которое мы хотим выполнять параллельно
2) Запустить поток Thread.start()
```kotlin
init {  
// создаем новый поток   
val secondThread = Thread(object:Runnable{  
        override fun run() {  
            repeat(100){  
                Log.d("MY", "Print * ${Thread.currentThread().name}")  
            }  
        }  
    })  
    // меняем имя по умолчанию  
    secondThread.name = "myThread"  
    // запускаем поток  
    secondThread.start()  
  
    // main-поток  
    repeat(100){  
        Log.d("MY", "Print + ${Thread.currentThread().name}")  
    }  
}
```
 
##### Простейший в Kotlin через метод thread 
В пакете cuncurrent есть метод thread, в который передаем лямбду, которую надо запустить и у это метод по умолчанию сразу запускается, так как у него параметр start=true
Под капотом у него код из п1. Простейший(через объект Thread в Java)
```kotlin
private fun runMultiByKotlin() {  
    thread(name = "myNewThreadByKotlin") {  
        repeat(100) {  
            Log.d("MY", "Print * ${Thread.currentThread().name}")  
        }  
    }  
    repeat(100) {  
        Log.d("MY", "Print - ${Thread.currentThread().name}")  
    }  
}
```

`Thread.sleep(1000L)` - усыпляет текущий поток на величину в миллисикундах, переданную в аргументе

### Демон-потоки (daemon threads)
Потоки в JVM делятся на два вида:
- **Пользовательские (user / non-daemon)** — обычные потоки. JVM **не завершится**, пока жив хотя бы один такой поток. `main` — пользовательский.
- **Демон-потоки (daemon)** — фоновые «обслуживающие» потоки. JVM **не ждёт** их: как только завершились все пользовательские потоки, JVM выключается и демоны **принудительно останавливаются** прямо посреди работы (даже если внутри `while(true)`).

Смысл: демон нужен для вспомогательной фоновой работы, которая не должна удерживать программу от завершения. Классический пример — поток сборщика мусора. См. [[Garbage collector]].

- Флаг ставится **до** `start()`: `thread(isDaemon = true) { … }` или `t.isDaemon = true`.
- Поток наследует «демонность» от родителя (поток, созданный из демона, тоже демон).
- **Осторожно**: демон могут убить в любой момент — `finally`-блоки и закрытие ресурсов (файлы, соединения) могут не выполниться. Поэтому в демонах **не** держат важную работу с ресурсами.

```kotlin
fun main() {  
    thread(name = "Simpliest") {  
        repeat(5) {  
            println("*")  
            sleep(1000)  
        }  
    }  
    // окончит свою работу, после того   
    // как все основные потоки завершатся,   
    // сам дальше не продолжит работу  
    thread(isDaemon = true) {  
        while(true) {  
            println("I am daemon")  
            sleep(1000)  
        }  
    }  
}
```
