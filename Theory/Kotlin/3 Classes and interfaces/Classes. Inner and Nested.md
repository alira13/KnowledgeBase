# Nested и Inner классы

Класс, объявленный внутри другого класса. В Kotlin по умолчанию — **nested** (вложенный, без ссылки на внешний), с ключевым словом `inner` — **inner** (внутренний, со ссылкой на внешний).

## Nested (по умолчанию) — как `static` в Java
Не хранит ссылку на объект внешнего класса, **не** видит его нестатические поля. Создаётся без экземпляра внешнего класса.
```kotlin
class Outer {
    private val x = 10
    class Nested {
        fun foo() = 5        // НЕ видит x внешнего класса
    }
}
val n = Outer.Nested()       // без объекта Outer
```

## Inner — со ссылкой на внешний объект
Хранит **неявную ссылку** на экземпляр внешнего класса, поэтому видит его поля. Создаётся только от объекта внешнего класса.
```kotlin
class Outer {
    private val x = 10
    inner class Inner {
        fun foo() = x        // видит x — есть ссылка на Outer
    }
}
val i = Outer().Inner()      // нужен объект Outer
```

## Разница (главное на собесе)
| | Nested | Inner |
|---|---|---|
| Ссылка на Outer | нет | **есть** (неявная) |
| Доступ к членам Outer | только статические | любые |
| Создание | `Outer.Nested()` | `outer.Inner()` |
| Аналог в Java | `static` вложенный | обычный внутренний |

## Почему это важно — утечки памяти
`inner`-класс (и **анонимные**/лямбды, захватывающие внешний объект) держат ссылку на Outer. Если такой объект переживёт Outer (попал в долгоживущий колбэк/`Handler`/статику), Outer **не соберётся** — утечка. Классика: анонимный `Runnable`/`Handler` внутри Activity. По умолчанию используйте **nested**; `inner` — только когда реально нужна ссылка на внешний объект. См. [[Memory leaks. Detection]], [[Handler, Looper, MessageQueue]].

## Вопрос-ловушка
«Внутренний класс в Kotlin по умолчанию inner или nested?» → **nested** (в отличие от Java, где обычный внутренний класс — inner). Чтобы получить доступ к внешним полям, нужно явно `inner`.
