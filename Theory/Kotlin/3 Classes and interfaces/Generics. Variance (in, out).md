Когда мы говорим о модификаторах **`in`** и **`out`** для типовых параметров, они применяются **только в дженериках** для обеспечения безопасности типов при работе с наследованием.
Эти концепции появились для **гарантированной безопасности типов**. Без них можно было бы нечаянно нарушить логику программы и получить ошибки во время выполнения.

Бывают:
 - **Исходные типы** - так как в котлин любые типы наследники Any, то как бы исходный тип только Any. Но у каждой пары вообще может быть исходный тип и производный. Например Child и listOfChild
 - **Производные типы (или **derived type**) — это тип, который создаётся на основе другого типа с добавлением новых возможностей. Производными могут быть классы, интерфейсы и коллекции.

| Производный тип               | Описание                                                                 |
| ----------------------------- | ------------------------------------------------------------------------ |
| **Наследование классов**      | `Child` — производный тип от `Parent`, расширяющий его функциональность. |
| **Реализация интерфейсов**    | `Dog` — производный тип от `Animal`, реализующий его поведение.          |
| **Обобщённые (generic) типы** | `Box<Int>` и `Box<String>` являются производными от `Box<T>`.            |
| **Nullable-тип**              | `String?` — производный тип от `String`, позволяющий `null`.             |
| **Ковариантность (`out`)**    | `Producer<String>` является производным от `Producer<Any>`.              |
| **Контравариантность (`in`)** | `Consumer<Any>` является производным от `Consumer<String>`.              |
**Вариантность** - сохранение совместимости присваивания исходных типов данных у производных типов. Как относятся друг к другу производные типы, если исходные находятся в оддной иерархии наследования

**Совместимость присваивания** - когда в переменную более общего типа можно положить объект частного типа.
```kotlin
val worker: Worker = Programmer("John")  
showName(worker)
```


 - Инвариантность(НЕ Вариантность) - можно присваивать только одинаковые типы. 
```kotlin
 // инвариантность если interface MyList<T> : MyCollection<T>
val workers:MyList<Worker> = myListOf<Programmer>(Programmer("Nick"), Programmer("Natalie"))  

```
 - Ковариантность - можем переменной родительского производного типа присвоить объект дочернего производного класса
	- Чтобы сделать дженерики ковариантными, надо использовать out для T. Это значит, что этот класс неизменяемый и может только отдавать данные наружу, а на вход для изменения не может ничего применять. Такой класс называется producer. При этом даже если неизменяемый класс содержит методы со входными данными, вполне безопасно помечать их аннотацией, так как эти методы действительно не изменяют класс `fun containsValue(value: @UnsafeVariance V): Boolean`
	 - Если мы делаем какой-то класс ковариантным, он должен быть НЕИЗМЕНЯЕМЫМ. Если ковариантный класс будет что-то принимать на вход, то это может привести к проблемам.
	- Поэтому в стандартных классах котлин неизменяемые классы инвариантны.
