Конструкторы используются для инициализации свойств объекта
При создании любого объекта конструктор вызвается ОБЯЗАТЕЛЬНО. Поэтому там удобно инициализировать все поля, он будет гарантировать, что они будут точно инициализированы.

Блоки init используются только в том случае, когда не получается использовать конструктор. То есть когда нужны выполнить какие-то доп. действия, да и просто распечатать что при создании объекта. В остальных случаях все параметры необходимо инициализировать в конструкторе. Конструкторы отличаются от методов тем, что их вызов обязателен. Поля внутри класса должны быть var

Если мы создаем хотя бы один свой конструктор, то пустой конструктор по умолчанию не создается

Можно из одного конструктора вызывать другой конструктор
```
class Rectangle{
	val width:Int
	val height:Int

	//значения по умолчанию
	constructor():this(0)

	// наш конструктор
	constructor(width:Int, height:Int){
		this.width = width
		this.height = height
	}

	// для создания квадрата вызываем другой конструктор, 
	чтобы не дублировать код
	constructor(size:Int):this(size, size){
	
	}
}
```

Первичный конструктор - конструктор, который в любом случае вызовется для создания объекта.
Чтобы создать первичный конструктор нужно прям в классе в скобках прописать поля., если нужно, добавить им значения по умолчанию. Если без val, то это просто аргументы конструктора, если с val, то это уже будут поля. В kotlin это наиболее распространенный способ инциализации, когда мы сразу все поля описываем в первичном конструкторе.
Если при создании объекта какие-то поля ОБЯЗАТЕЛЬНЫ для заполнения пользователем, им НЕ НАДО присваивать значения по умолчанию
Если мы хотим просто передать какие-то параметры в конструктор, но не хотим при этом создавать свойство, то нам не нужно использовать val


В Kotlin есть несколько способов инициализации объектов: **первичный конструктор**, **вторичные конструкторы** и **инициализационные блоки (`init`)**. Давай разберем их подробно.

---

## 🔹 **Первичный конструктор**

В Kotlin первичный конструктор объявляется прямо в заголовке класса:

```kotlin
class Person(val name: String, val age: Int)
```

Тут:

- **`val name` и `val age`** — это свойства, которые сразу создаются и инициализируются значениями из конструктора.
- **Нет тела конструктора** — если дополнительная логика не нужна, писать `init`-блок не обязательно.

### 📌 Добавление логики с `init`

Если нужно выполнить дополнительные действия при создании объекта (например, валидацию данных), используют **инициализационные блоки `init`**:

```kotlin
class Person(val name: String, val age: Int) {
    init {
        require(age > 0) { "Возраст должен быть положительным" }
        println("Создан объект Person с именем $name и возрастом $age")
    }
}
```

- `init` выполняется сразу после вызова первичного конструктора.
- Можно объявить **несколько** `init`-блоков — они выполняются в порядке написания.

---

## 🔹 **Вторичные конструкторы**

Иногда первичного конструктора недостаточно, и нужны **альтернативные способы создания объекта**. В Kotlin можно объявить **вторичные конструкторы** с ключевым словом `constructor`:

```kotlin
class Person {
    var name: String
    var age: Int

    constructor(name: String) {
        this.name = name
        this.age = 18  // значение по умолчанию
    }

    constructor(name: String, age: Int) {
        this.name = name
        this.age = age
    }
}
```

### Важные моменты:

- Вторичные конструкторы **обязательно должны вызывать первичный** (если он есть) через `this(...)`:

```kotlin
class Person(val name: String, val age: Int) {
    constructor(name: String) : this(name, 18) // вызывает основной конструктор
}
```

- Если в классе **нет первичного конструктора**, `this(...)` можно не использовать.

---

## 🔹 **Разница между `init` и вторичными конструкторами**

||`init`|Вторичные конструкторы|
|---|---|---|
|Когда выполняется?|Сразу после вызова первичного конструктора|Когда вызывается вторичный конструктор|
|Где объявляется?|Внутри класса|Через `constructor(...)`|
|Можно ли несколько?|Да|Да|
|Доступ к `val/var` из первичного конструктора|Да|Только после вызова `this(...)`|

## 🔹 **Примеры использования**

### 1️⃣ `init` для проверки аргументов:

```kotlin
class Car(val model: String, val year: Int) {
    init {
        require(year > 1900) { "Год выпуска должен быть больше 1900" }
    }
}
```

### 2️⃣ Вторичный конструктор для альтернативного создания объекта:

```kotlin
class Employee(val name: String, val position: String) {
    constructor(name: String) : this(name, "Стажер")
}
```

### 3️⃣ Класс без первичного конструктора:

```kotlin
class Book {
    var title: String
    var author: String

    constructor(title: String, author: String) {
        this.title = title
        this.author = author
    }
}
```

---

## 🔹 **Вывод**

- **Первичный конструктор** — удобный и компактный, особенно для data-классов.
- **Блоки `init`** — полезны для инициализации и валидации.
- **Вторичные конструкторы** — применяются, если нужно несколько вариантов создания объекта.

В 90% случаев достаточно **первичного конструктора + `init`**. Вторичные конструкторы нужны реже, например, когда у класса **сложная логика инициализации**.
