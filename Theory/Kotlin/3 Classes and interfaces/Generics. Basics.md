# Обобщённые типы (Generics)

**Дженерики** позволяют параметризовать класс/функцию **типом**: логика одна, а тип данных подставляется при использовании. Тип обозначают заглавной буквой в угловых скобках (`T`, `E`, `K`, `V`).

## Зачем
- **Типобезопасность на этапе компиляции**: `List<String>` не даст положить `Int` — ошибка компиляции, а не падение в рантайме.
- **Переиспользование**: один `Box<T>` работает с любым типом без дублирования кода.
- **Без приведения типов**: достаём из `List<String>` сразу `String`, без `as`.

```kotlin
class Box<T>(val value: T)          // класс с параметром типа
fun <T> firstOf(list: List<T>): T = list[0]   // обобщённая функция

val b = Box("hi")   // T = String, вывелся автоматически
```

## Ограничения (bounds)
Сузить допустимые типы через **upper bound**: `T` обязан быть подтипом.
```kotlin
fun <T : Number> sum(list: List<T>): Double = list.sumOf { it.toDouble() }
// T : Number → внутри доступны методы Number (toDouble и т.д.)
```
По умолчанию верхняя граница — `Any?` (можно nullable). Несколько границ — через `where`.

## Вариантность (кратко)
`out T` — ковариантность (producer, только отдаёт), `in T` — контравариантность (consumer, только принимает), `*` — star-projection. Подробно и с примерами — в [[Generics. Variance (in, out)]].

## Стирание типов (type erasure)
На JVM параметр типа **стирается** в рантайме: `List<String>` и `List<Int>` — в байткоде один `List`. Поэтому нельзя `if (x is List<String>)` и нельзя `T::class` напрямую. Обход — **reified** в inline-функциях. См. [[Generics. Type erasure]], [[Functions. Inline, noinline, crossinline, reified]].

## Частые вопросы
- Зачем дженерики? → типобезопасность + переиспользование без дублирования и без каста.
- `List<Number>` можно присвоить `List<Int>`? → нет по умолчанию (инвариантность); нужна ковариантность (`out`).
- Почему нельзя `T()` создать объект параметра типа? → из-за стирания (нет конструктора в рантайме); нужен фабричный параметр или reified.
