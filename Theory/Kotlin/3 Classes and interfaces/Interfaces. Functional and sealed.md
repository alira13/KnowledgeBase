Для того, чтобы наделить класс несколькими функциональностями. Но нельзя наследоваться от нескольких классов.

Выбор между интерфейсом и наследованием:
 - Если объект является представителем этого родительского класса, то используем наследование. Кошка = семейство кошачьих. 
- Если объект просто выполняет какие-то доп функции, то используем интерфейс.
Бухгалтер != клинер, он просто может убраться на своем рабочем месте.


Общее между абстрактными классами и интерфейсами
 - Интерфейс может содержать реализацию метода как и абстрактный класс, но обычно не пишем
 - Все методы интерфейса по умолчанию открытые и доступны для переопределения?
 - Нельзя создать объект интерфейса

Отличие абстрактных классов от интерфейсов
 - Абстрактные классы говорят, чем является объект, интерфейсы только описывают доп поведение класса
 - Нельзя наследовать несколько абстрактных классов, но можно реализоввывать сколько угодно интерфейсов
 - Конструкторы. У абстрактных классов они есть и все наследних обязаны их вызвать. У интерфейсов нет конструкторов.

Интерфейс - это контракт, и когда класс реализует интерфейс, он обязан реализовать методы интерфейса. Но если класс абстрактный реализует интерфейс, то он не обязан переопределять методы интерфейса.

### Функциональный интерфейс

Фцнкциональтный интерфейс - интерфейс с 1 методом. 
Можно не создавать реализацию интерфейса, а просто передать лямду
Можно добавить в интерфейс ключевое слово fun, это означает что мы гарантируем что этот интерфейс будет функциональным и мы не сможем добавить туда еще методы, и компилятор будет за этим следить, и не скомпилит если добавим еще метод

 - тогда можно его создать класс, который реализует этот интерфйс как обычный интерфейс, 
 - можно создать анонимный класс, реализующий этот интерфейс
 - но можно и вместо него использовать лямбду

### Sealed интерфейс

Позволяют ограничить наследование. По факту содержат ограниченное количество реализаций этого интерфейса, которые все описываются внутри тела интерфейса

Например используется в паттерне Команда
В MVI - один компонент взаимодействует с другим посредствам команд, при этом все команды перечисляются в sealed-интерфейса
Доступ осуществляется через ИмяSealesИнтерфейса.ИмяРеализации

Часто используют в state для экранов. Причем внутри делают data object классы, чтобы была возмодность красиво распечатать toString()
