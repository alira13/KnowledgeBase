### Наследование, upcast, downcast, smartcast

По умолчанию все методы и классы в Kotlin - final - т.e от них нельзя наследоваться, они не могут иметь потомков. Модификатор open - Чтобы была возможность создать наследника для класса
 - Создаем родительский класс с модификатором open. 
 - Если нужно будет переопределить методы родительского класса, то их тоже помечаем open
 - Создаем дочерний класс, после конструктора ставим : и вызываем конструктор родительского класса и передаем туда параметры. Если дочернему классу нужны его НОВЫЕ поля, то добавляем их в его конструктор val
 - Если переопределяем методы родительского, то пишем Override

Все дочерние классы имеют доступ к не private полям родительского класса
В конструкторе дочернего класса вызывается по умолчанию конструктор родительского класса

**Upcast** (val worker:Man = Worker()) - приведение к родительскому типу. Ребенок UP(растет) до родителя. Тогда мы можем вызывать и обращаться к тем свойствам и методам, которые есть только у родительского

**Downcast** (man as worker) - приведение к дочернему классу-ребенку. Взрослый уменьшился в росте.

**Smartcast** - умное приведение типа, которое делает компилятор за нас. Например после проверки is.

```
// Общее
open class Man(val name){
	fun live()
}

//Частное
class Worker(workerName:String):Man(name=workerName){
	fun work()
}

// UPCAST работник уволился и стал обычным человеком, ему не надо работать. 
// Настроение UP
val worker:Man = Worker() работать
worker.live()

// UPCAST работник снова нашел работу, теперь он будет 5 дней работать и 2 отдыхать. 
//Настроение DOWN
(worker as Worker).work()
(worker as Worker).live()

//smartcast - автоопределение компилятором типа объекта.  после проверки
if(man is Worker) 
// это лишнее, компилятор понимает что если вошли в условие, то тип точно Worker
//	(man as Worker).work
	man.work()
```

super - используется для вызова родительских методов в дочерней функции

Можно наследоваться только от 1 класса, но от многих интерфейсов


Полиморфизм - когда вызвается родительский метод, его реализация будет зависеть от дочернего объекта, из которого он вызван.

В дочерних классах можно переопределять не только МЕТОДЫ, но и СВОЙСТВА. То есть в абстрактном классе мы можем в первичном конструкторе сделать свойства open и  в дочернем переопределить через override
