# Стирание типов (type erasure)

**Стирание типов** — то, что после компиляции никаких дженериков не остаётся. Параметр типа существует только для компилятора: он проверяет корректность, расставляет приведения и выбрасывает информацию о `T`. В байткоде `List<String>` и `List<Int>` — один и тот же `List`, а `T` превращается в `Object` (или в верхнюю границу, если она задана).

## Зачем так сделали
Дженерики появились в Java 5, когда байткод и библиотеки уже существовали. Стирание дало **обратную совместимость**: старый код без дженериков и новый работают вместе, JVM менять не пришлось. Kotlin компилируется в тот же байткод и наследует это ограничение.

## Что происходит на самом деле
Дженерик — это синтаксический сахар: под капотом хранится `Object`, а приведение к нужному типу компилятор вставляет за вас.
```kotlin
// эти два класса после компиляции работают одинаково:
private class Box(val value: Any?)          // руками
private class ParamBox<T>(val value: T)     // T стирается до Object

fun main() {
    val b1 = Box(10)
    val bv = b1.value as Int + 10           // каст пишем сами

    val p1 = ParamBox(30)
    val pv = p1.value + 50                  // каст вставил компилятор
}
```
Разница только в том, кто отвечает за ошибку: в первом случае `ClassCastException` в рантайме, во втором — ошибка компиляции.

## Главное следствие: нельзя проверить параметр в рантайме
```kotlin
fun <T> doSmthWithList(el: List<T>) {
    when (el) {
        // is List<String> -> ...   ОШИБКА компиляции: cannot check for instance of erased type
        // is List<Box>    -> ...
    }
}
```
Компилятор запрещает это не из вредности: после стирания обе ветки превратились бы в одну и ту же проверку `is List`, и вторая была бы недостижима — код без смысла.

А вот проверка **самого объекта** `T` работает: в `when` участвуют конкретные классы, а не параметр типа.
```kotlin
fun <T> doSmth(el: T) {
    when (el) {                 // el стёрт до Any?, но проверяем реальные классы
        is String -> println("This is String")
        is Box -> println("This is Box")
        else -> println("I dont know")
    }
}
```

Разрешена и **звёздная проекция** — «список чего угодно», ведь она ничего не утверждает про элементы:
```kotlin
if (el is List<*>) println("список, но чего — неизвестно")
```

## Что ещё запрещено из-за стирания
- `T::class` и `T()` — в рантайме нет ни класса, ни конструктора параметра.
- `Array<T>` создать напрямую нельзя — нужен `arrayOfNulls` + каст или `reified`.
- **Перегрузка по параметру типа**: `fun f(x: List<String>)` и `fun f(x: List<Int>)` — после стирания одинаковые сигнатуры, конфликт (обходится `@JvmName`).
- Ловить обобщённые исключения (`catch (e: MyException<T>)`) нельзя.

## Обход: reified
В **inline**-функции тело подставляется в место вызова, поэтому конкретный тип известен на этапе компиляции — его можно «материализовать» словом `reified`.
```kotlin
inline fun <reified T> Any.isTypeOf(): Boolean = this is T   // теперь можно!
inline fun <reified T> emptyArrayOf(): Array<T> = arrayOf()

val ok = "hello".isTypeOf<String>()   // true
```
Именно так работают `filterIsInstance<T>()`, `Gson().fromJson<T>()`-обёртки и `koinViewModel<T>()`. Ограничение: `reified` возможен **только** у `inline`-функций (у классов и обычных функций — нет).

Второй обход, когда inline не подходит: передать тип **явным аргументом** — `Class<T>` / `KClass<T>` (так делают Retrofit, Room, старые Java-API).

## Грабли
- Дженерики стёрты, но **сигнатуры полей и методов** сохраняют информацию в метаданных класса — её достаёт рефлексия (`ParameterizedType`), на этом построены `TypeToken` у Gson и `typeOf<T>()` у kotlinx.serialization. То есть «стёрто полностью» — упрощение: стёрты значения в рантайме, объявления частично остались.
- Приведение `list as List<String>` компилируется с предупреждением *unchecked cast*: проверки не будет, `ClassCastException` прилетит позже, при первом чтении элемента.
- `reified` заставляет функцию быть `inline` → её нельзя вызвать из Java и нельзя использовать с приватными членами.

## Вопросы-ловушки
- Почему `List<String>` и `List<Int>` нельзя перегрузить? → после стирания это один и тот же `List`, сигнатуры совпадают.
- Как обобщённая функция всё-таки узнаёт тип? → `reified` + `inline` (тип подставляется на этапе компиляции) или явно переданный `KClass`/`TypeToken`.
- Есть ли стирание в C#? → нет, там reified generics на уровне CLR; ограничение специфично для JVM.
