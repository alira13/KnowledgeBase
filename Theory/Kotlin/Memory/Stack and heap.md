Стек и куча (heap) — это области памяти, которые используются программами для выполнения различных операций. Они управляют тем, как данные хранятся и обрабатываются в оперативной памяти компьютера.

---

### **Стек (Stack)**

**1. Что это?** Стек — это область памяти, где хранятся локальные переменные, вызовы функций и данные, которые нужны только на время выполнения этих функций.

**2. Принципы работы:**

- Работает по принципу **LIFO** (Last In, First Out): последним добавленным элементом будет первым удалён.
- Быстрое выделение и освобождение памяти (при завершении функции стек очищается автоматически).

**3. Особенности:**

- Память выделяется статически (размер задаётся при компиляции).
- Каждый вызов функции добавляет новый фрейм (блок данных) в стек.
- После завершения функции этот фрейм удаляется.
- Ограничен по размеру (обычно небольшой).

**4. Применение:**

- Хранение локальных переменных.
- Хранение адресов возврата при вызове функций.
- Хранение параметров функций.

**5. Пример работы стека:**

```kotlin
fun main() {
    val x = 10 // Локальная переменная хранится в стеке
    val result = factorial(5)
    println(result)
}

fun factorial(n: Int): Int {
    return if (n == 1) 1 else n * factorial(n - 1)
}
```

Каждый вызов `factorial` добавляет новый фрейм в стек. Когда функция завершает выполнение, фрейм удаляется.

---

### **Куча (Heap)**

**1. Что это?** Куча — это область памяти, где хранятся данные, которые существуют дольше, чем время выполнения функции. Она используется для объектов и динамического выделения памяти.

**2. Принципы работы:**

- Доступ к данным осуществляется через ссылки (указатели).
- Память выделяется и освобождается вручную или автоматически (например, с помощью сборщика мусора в Java/Kotlin).

**3. Особенности:**

- Память выделяется динамически (размер определяется во время выполнения программы).
- Более медленная, чем стек, из-за необходимости управления памятью.
- Гораздо больший объём памяти, чем у стека.
- Требует управления сборщиком мусора.

**4. Применение:**

- Хранение объектов (например, экземпляров классов).
- Хранение переменных, которые нужны после завершения функции (например, глобальных объектов или результатов работы).

**5. Пример работы кучи:**

```kotlin
class Person(val name: String)

fun main() {
    val person = Person("Alice") // Объект хранится в куче
    println(person.name)
}
```

Объект `Person` создаётся в куче, а ссылка на него хранится в стеке.

---

### **Основные отличия между стеком и кучей**

|**Критерий**|**Стек (Stack)**|**Куча (Heap)**|
|---|---|---|
|**Принципы работы**|LIFO (последний вошёл — первый вышел).|Произвольное размещение и доступ к памяти.|
|**Выделение памяти**|Статическое (фиксированный размер).|Динамическое (во время выполнения программы).|
|**Скорость работы**|Быстрее, так как память выделяется и очищается автоматически.|Медленнее, так как требуется управление сборщиком мусора.|
|**Размер**|Обычно небольшой (ограничен стеком вызовов).|Гораздо больше, чем стек.|
|**Хранимые данные**|Локальные переменные, параметры функций, адреса возврата.|Объекты, глобальные данные, данные с длительным временем жизни.|
|**Очистка памяти**|Автоматическая при завершении функции.|Автоматическая или ручная (сборщик мусора).|
|**Доступ к памяти**|Прямой (более быстрый доступ).|Косвенный через ссылки/указатели.|

---

### **Пример: Взаимодействие стека и кучи**

```kotlin
class Car(val model: String)

fun main() {
    val x = 5 // Хранится в стеке
    val car = Car("Tesla") // Объект хранится в куче, ссылка - в стеке
    println(car.model)
}
```

1. Переменная `x` хранится в стеке.
2. Объект `Car` создаётся в куче, а ссылка на него (`car`) — в стеке.

---

### **Резюме**

- **Стек**: используется для временных данных, таких как локальные переменные и вызовы функций. Быстр, но ограничен по размеру.
- **Куча**: используется для хранения объектов и данных с длительным временем жизни. Обладает большим объёмом памяти, но работает медленнее.
