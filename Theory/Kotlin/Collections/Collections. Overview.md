В Kotlin **не-nullable примитивные типы** (например, `Int`, `Boolean`, `Double` и т. д., без `?`) **не имеют значения по умолчанию**. Если вы объявляете переменную такого типа, её **обязательно нужно инициализировать**, иначе код не скомпилируется.

---

### **1. Не-nullable примитивные типы и их поведение**

Примитивные типы в Kotlin:

|Тип|Пример значения (при инициализации)|Примечание|
|---|---|---|
|`Int`|`0`|32-битное целое число.|
|`Long`|`0L`|64-битное целое число.|
|`Float`|`0.0f`|32-битное число с плавающей точкой.|
|`Double`|`0.0`|64-битное число с плавающей точкой.|
|`Boolean`|`false`|Логический тип (истина/ложь).|
|`Char`|`'\u0000'`|Null-символ Unicode (нулевой символ).|
|`Byte`|`0`|8-битное целое число.|
|`Short`|`0`|16-битное целое число.|

---

### **2. Локальные переменные**

Для локальных переменных **не-nullable примитивного типа** значение по умолчанию отсутствует, и их необходимо явно инициализировать перед использованием.

Пример (ошибка компиляции без инициализации):

kotlin

CopyEdit

`fun main() {     var x: Int     // println(x) // Ошибка: переменная не инициализирована     x = 10     println(x) // 10 }`

---

### **3. Свойства класса**

Для свойств класса Kotlin также требует инициализации, если тип не-nullable. Свойства могут быть инициализированы:

- **Сразу при объявлении.**
- **В конструкторе класса.**

Пример:

kotlin

CopyEdit

`class Example {     var age: Int = 0 // Инициализация при объявлении     var isStudent: Boolean      init {         isStudent = false // Инициализация в блоке init     } }`

Использование:

kotlin

CopyEdit

`fun main() {     val example = Example()     println(example.age)        // 0     println(example.isStudent)  // false }`

---

### **4. Массивы примитивных типов**

Если вы создаете массив примитивного типа (например, `IntArray`, `BooleanArray`), элементы автоматически инициализируются значениями по умолчанию для соответствующего типа:

|Тип массива|Значение по умолчанию элементов|
|---|---|
|`IntArray`|0|
|`BooleanArray`|false|
|`DoubleArray`|0.0|

Коллекция— группа с переменным количеством элементов (или нулём элементов), которые используются для решения какой-либо задачи.  
  

- _List_ (список) - упорядоченная коллекция, в которой к элементам можно обращаться по индексам — целым числам, отражающим положение элементов в коллекции. Идентичные элементы (дубликаты) могут встречаться в списке более одного раза. Примером списка является предложение: это группа слов, их порядок важен, и они могут повторяться.
- _Set_ (множество) - коллекция уникальных элементов. Отражает математическую абстракцию множества: группа объектов без повторов. Как правило, порядок расположения элементов здесь не имеет значения. Примером множества является алфавит.
- _Map_ (словарь, ассоциативный список) - набор из пар "ключ-значение". Ключи уникальны и каждый из них соответствует ровно одному значению. Значения могут иметь дубликаты. Ассоциативные списки полезны для хранения логических связей между объектами, например, ID сотрудников и их должностей.

Есть два вида интерфейсов, предоставляющих каждый из этих типов:

- _неизменяемый_ ( _read-only_) - предоставляет операции, которые дают доступ к элементам коллекции.
- _изменяемый_ (_mutable_) - расширяет предыдущий интерфейс и дополнительно даёт доступ к операциям добавления, удаления и обновления элементов коллекции.

Обратите внимание, что изменяемую коллекцию не требуется объявлять с помощью ключевого слова [`var`](https://kotlinlang.ru/docs/properties.html). Связано это с тем, что изменения вносятся в изначальные объекты коллекции без изменения ссылки на саму коллекцию. Но если вы объявите коллекцию с помощью `val` и попытаетесь ее перезаписать, то получите ошибку компиляции.
