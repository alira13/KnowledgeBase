# Scope-функции (let, run, with, apply, also)

**Scope-функции** — пять функций стандартной библиотеки, которые выполняют блок кода **в контексте объекта**. Они не добавляют новых возможностей: любой такой код можно написать без них. Их ценность — читаемость: объект не нужно называть по имени в каждой строке, а временные переменные не утекают наружу.

Различаются они всего по двум признакам:
1. **Как передан объект** — как `this` (receiver, имя можно опустить) или как `it` (обычный аргумент лямбды).
2. **Что возвращается** — сам объект или результат лямбды.

Из этих двух признаков выводится вся таблица — заучивать не нужно.

| Функция | Объект | Возвращает | Extension | Когда применять |
| --- | --- | --- | --- | --- |
| `let` | `it` | результат лямбды | ✅ | работа с nullable через `?.let`, преобразование в конце цепочки |
| `also` | `it` | сам объект | ✅ | побочное действие: лог, отладка, регистрация |
| `apply` | `this` | сам объект | ✅ | настройка только что созданного объекта |
| `run` | `this` | результат лямбды | ✅ | несколько операций над объектом с возвратом результата |
| `with` | `this` | результат лямбды | ❌ (обычная функция) | много обращений к свойствам одного объекта |

Мнемоника: `apply`/`also` возвращают **объект** (значит, годятся в середину цепочки), `let`/`run`/`with` — **результат**. `this` удобен, когда внутри вызываются методы объекта; `it` — когда объект передаётся куда-то дальше как аргумент.

## let — nullable и преобразования
```kotlin
val name: String? = "Kotlin"
name?.let {
    println("Длина: ${it.length}")   // выполнится только если name != null
}

val upper: String? = getName()?.let { it.uppercase() }
```
Внутри `let` нет никакой магии — это обычная обобщённая extension-функция:
```kotlin
inline fun <T, R> T.myLet(block: (T) -> R): R = block(this)
```
За null-безопасность отвечает **не `let`, а оператор `?.`**: если ссылка `null`, вызов вообще не происходит и выражение возвращает `null`. `let` можно вызвать и на nullable-объекте напрямую (`name.let { }`), но тогда внутри `it` будет nullable — проверять придётся руками.

## also — побочное действие
Возвращает объект нетронутым, поэтому вставляется в любую цепочку, ничего не ломая.
```kotlin
inline fun <T> T.myAlso(block: (T) -> Unit): T { block(this); return this }

val items = listOf(1, 2, 3)
    .also { println("Загрузили: $it") }      // лог, цепочка продолжается
    .filter { it > 1 }
```
Типичное применение — логирование, отправка аналитики, `requireNotNull`-проверки.

## apply — настройка объекта
```kotlin
val person = Person().apply {
    name = "Bob"          // this.name, this можно опустить
    age = 30
}
```
Заменяет паттерн Builder там, где его нет: создали объект и сразу сконфигурировали. В Android — классика для `Intent`, `Bundle`, `Paint`, `Fragment`:
```kotlin
startActivity(Intent(this, DetailsActivity::class.java).apply {
    putExtra("id", 42)
})
```

## run — вычисление на объекте
```kotlin
val result = "Kotlin".run { uppercase() }    // this подразумевается
```
Есть и форма **без объекта** — просто блок, ограничивающий область видимости и возвращающий результат:
```kotlin
val config = run {
    val raw = loadRaw()
    parse(raw)             // временные переменные не утекают наружу
}
```

## with — много обращений к одному объекту
```kotlin
val description = with(person) {
    "Имя: $name, возраст: $age"
}
```
Отличие от `run` только синтаксическое: `with(obj) { }` — обычная функция с аргументом, `obj.run { }` — extension. Поэтому на nullable удобнее `obj?.run { }`, а `with` для этого не годится.

## Родственники: takeIf и takeUnless
Формально не входят в пятёрку, но решают ту же задачу — вписать условие в цепочку:
```kotlin
val valid = input.takeIf { it.isNotBlank() }        // сам объект или null
val fallback = input.takeUnless { it.isBlank() } ?: "default"
```

## Как выбирать
Один вопрос: **что нужно получить на выходе?**
- нужен тот же объект → `apply` (меняешь его) или `also` (просто делаешь что-то рядом);
- нужен другой результат → `let` (объект как аргумент) или `run`/`with` (объект как receiver);
- объект может быть `null` → `?.let` или `?.run`.

## Грабли
- **Вложенные scope-функции** превращают код в кашу: два `let` подряд — и уже неясно, к чему относится `it`. Спасает явное имя параметра: `user?.let { user -> ... }`.
- **Затенение `this`** в `apply`/`run` внутри класса: `this` теперь объект-receiver, а не экземпляр класса; до внешнего добираются через `this@MyClass`.
- **`?.let` вместо `if`** там, где нужен и else-случай: `if (x != null) ... else ...` читается лучше, чем `x?.let { } ?: run { }`.
- `also`/`apply` возвращают объект **всегда** — даже если внутри лямбды посчитано что-то полезное, оно потеряется.
- Все пять — **inline**, поэтому лямбда не создаёт объекта и допускает нелокальный `return`. Внутри `?.let` `return` выходит из внешней функции — легко получить неожиданный ранний выход.

## Вопросы-ловушки
- Чем `apply` отличается от `run`? → `apply` возвращает сам объект, `run` — результат лямбды; объект в обоих — `this`.
- Чем `let` отличается от `also`? → возвращаемым значением: `let` — результат лямбды, `also` — объект.
- Чем `with` отличается от `run`? → `with` не extension-функция, поэтому её нельзя вызвать через `?.`.
- Кто на самом деле обеспечивает null-безопасность в `name?.let { }`? → оператор `?.`, а не `let`.
- Что вернёт `person.apply { name = "Bob" }.let { it.name }`? → `"Bob"`: `apply` отдал объект, `let` — результат лямбды.
