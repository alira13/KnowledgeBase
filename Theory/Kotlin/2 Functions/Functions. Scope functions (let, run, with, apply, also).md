
Scope-функции в **Kotlin** — это специальные функции (`let`, `run`, `with`, `apply`, `also`), которые позволяют **изменять объект или выполнять над ним действия в ограниченной области видимости (scope)**.

То есть когда мы вызываем у объекта scope-функцию, мы говорим, что мы будем работать внутри его контекста(определяется фигурными скобками) и сам объект будет it
🔹 **Главное отличие между ними** – **как передается объект (this или it)** и **что возвращает функция (объект или результат лямбды)**.

## **🔹 2. Разбор каждой scope-функции с примерами**

### **✅ 1) `let` — для работы с `nullable` объектами**

Используется, когда нужно **безопасно работать с `null`-объектами** или **изменить объект перед передачей в другую функцию**.

```kotlin
//как реализована в kotlin
inline fun <T, R> R.myLet(lambda: (R) -> T) {  
    lambda(this)  
}
```
Функцию let можно применить и к не null-объектам. 

То есть сама функция let лишь вызывает lambda, но работает с не null, потому что к name применен безопасный метод вызова, который гласит, что если переменная не null, то воспринимай и работай с ней не как с null, а если она null, просто ничего не делай и верни null.

То есть по сути let это универсальная функция расширения, которая может делать что угодно(этим управляет lambda) и c каким угодно типом. который она расширяет(потому что let - это дженерик функция расширения типа T, возвращающая тип R)

Но чаще всего используется в комбинации с безопасным вызовом и с nullable-типами
Можем ли мы вызвать у nullable объекта без безопасного вызова let? Да, но у нас будет ограничение на lambda, она должна уметь работать с nullable-объектами.

```kotlin
val name: String? = "Kotlin"

name?.let {
    println("Длина строки: ${it.length}") // it → "Kotlin"
}
```

👉 Если `name == null`, код внутри `let` **не выполнится**.

**📌 Вопрос на собеседовании:**

> В каких случаях `let` может быть полезен?  
> ✅ Ответ: когда переменная `nullable`, например `val name: String? = getName()?.let { it.uppercase() }`

### **✅ 2) `also` — выполняет действие и возвращает объект**

Используется, когда нужно **логировать, дебажить или делать дополнительные операции**.

Работает как и let, только возвращает ВСЕГДА тип, с которым он работает.

`val person = Person("Alice", 25).also {     println("Создан объект: $it") }`

📌 Полезно для **логирования** или **цепочки вызовов**

```kotlin
inline fun <T> T.myAlso(lambda: (T) -> Unit): T {  
    lambda(this)  
    return this  
}  
  
fun main() {  
    val items = listOf(1, 2, 3)  
  
    // пропускает через себя элементы и никак их не меняет  
    // просто их возвращает и совершает еще какое-то действие,    // например логирует  
    val myAlsoItems = items.myAlso {  
        println("Call also $it")  
    }  
  
    println(myAlsoItems)  
      
    val alsoItems = items.also {  
        it + 2  
        println("Call also $it")  
    }  
    println(alsoItems)  
}
```
### **✅ 2) `run` — выполняет код и возвращает результат**

Используется, когда нужно **выполнить несколько операций над объектом** и **вернуть вычисленный результат**.

```kotlin
val result = "Hello".run {
    this.uppercase()
}
println(result) // "HELLO"
```

📌 `this` можно опустить:

```kotlin
val result = "Kotlin".run { uppercase() }
```

**📌 Вопрос на собеседовании:**

> В чем разница между `let` и `run`?  
> ✅ Ответ: `let` использует `it`, а `run` — `this`. `let` чаще применяется для `nullable`, а `run` — для удобства вызова методов.

---

### **✅ 3) `with` — удобный способ работы с объектом**

Используется, когда нужно **много раз обращаться к свойствам объекта**.

```kotlin
val person = Person("Alice", 25)

val description = with(person) {
    "Имя: $name, Возраст: $age"
}
println(description) // "Имя: Alice, Возраст: 25"
```

📌 В отличие от `run`, `with` **не является extension-функцией**, а просто принимает объект.

**📌 Вопрос на собеседовании:**

> Чем `with` отличается от `run`?  
> ✅ Ответ: `with(obj) {}` – обычная функция, `obj.run {}` – extension-функция.

---

### **✅ 4) `apply` — изменяет объект и возвращает его**

Используется, когда нужно **изменить объект и сразу вернуть его**.

```kotlin
val person = Person("Alice", 25).apply {
    name = "Bob"
    age = 30
}
println(person) // Person(name=Bob, age=30)
```

📌 **Используется для настройки объектов (например, Builder Pattern).**

**📌 Вопрос на собеседовании:**

> Чем `apply` отличается от `run`?  
> ✅ Ответ: `apply` возвращает **сам объект**, `run` — **результат выполнения лямбды**.

## **🔹 3. Когда использовать какую scope-функцию?**

|**Ситуация**|**Лучшая функция**|
|---|---|
|Нужно обработать `null`-объект|`let`|
|Нужно выполнить лямбду и вернуть результат|`run`|
|Работа с уже существующим объектом|`with`|
|Настройка объекта (изменение полей)|`apply`|
|Логирование или отладка|`also`|

## **🔹 4. Вопросы на собеседовании по scope-функциям**

### **📌 1. Чем `apply` отличается от `run`?**

✅ `apply` возвращает сам объект, `run` — результат выполнения лямбды.

### **📌 2. Чем `let` отличается от `also`?**

✅ `let` используется, когда нужен **результат лямбды**, `also` — когда **важно вернуть объект, но сделать что-то дополнительно**.

### **📌 3. Какой смысл у `with` и чем он отличается от других функций?**

✅ `with` **не является extension-функцией**. Это обычная функция, которая помогает работать с объектом.

### **📌 4. Что произойдет, если `null`-объект использовать в `let`?**

✅ Код внутри `let` **не выполнится**, так как он вызывается через `?.`.

### **📌 5. Как можно заменить `with` на `run`?**

✅ `with(obj) { }` можно заменить на `obj.run { }`.

---

## **🔹 5. Итог**

- **Scope-функции помогают писать чистый код**, особенно в цепочках вызовов.
- **`let`** → работает с `nullable`.
- **`run`** → выполняет код и возвращает результат.
- **`with`** → удобен для работы с объектом.
- **`apply`** → изменяет объект и возвращает его.
- **`also`** → выполняет доп. действия и возвращает объект.
