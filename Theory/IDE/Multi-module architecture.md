# Многомодульная архитектура (Multi-module)

Разбиение проекта на несколько Gradle-модулей вместо одного `:app`. Классический senior-вопрос: «зачем и когда НЕ нужно».

## Зачем
- **Скорость сборки** — Gradle пересобирает только изменённые модули и их зависимости; независимые модули собираются параллельно и берутся из build cache. Главный практический выигрыш.
- **Инкапсуляция** — модуль отдаёт наружу только публичное API, реализацию прячет (`internal`, отдельный `:api`/`:impl`).
- **Явные границы и правила зависимостей** — компилятор не даст `:feature-a` зависеть от `:feature-b`, если это запрещено графом.
- **Переиспользование** и параллельная работа команд без конфликтов.
- **Изоляция для тестов** и возможность feature-модулей (Dynamic Feature).

## Когда НЕ нужно
- Маленькое приложение / MVP / прототип — накладные расходы на настройку графа и Gradle превысят выгоду.
- Команда из 1–2 человек, простая доменная область.
- Преждевременное дробление рождает «модуль ради модуля» и сложную навигацию.

## Типовое разбиение
```
:app                 // сборка графа, DI, навигация верхнего уровня
:core:ui             // дизайн-система, темы, общие composable
:core:common         // утилиты, Result, extensions
:core:network        // Ktor/Retrofit клиент
:core:database       // Room
:feature:login       // экран(ы) фичи: ui + presentation
:feature:feed
:domain              // use cases, доменные модели (может быть pure Kotlin/KMP)
:data                // репозитории, мапперы
```

## Правила зависимостей
- Зависимости направлены внутрь: `feature → domain → data` (или по слоям Clean). См. [[Clean architecture]].
- `:feature` не зависит от другого `:feature` напрямую — общение через `:domain`/навигацию/callbacks.
- `api` vs `implementation` в Gradle: `implementation` не протекает транзитивно (быстрее пересборка), `api` — экспортирует зависимость дальше.

## Инструменты
- **Convention plugins** (`build-logic`) — единая конфигурация модулей, без копипасты в каждом `build.gradle`.
- **Version catalog** (`libs.versions.toml`) — централизованные версии зависимостей. См. [[Dependencies via .toml]].
- **KMP** — общий `:domain`/`:data` между Android и iOS. См. [[KMP. Kotlin Multiplatform]].

## На собесе часто спрашивают
- Как ускоряется сборка? (инкрементальность + параллелизм + build cache)
- api vs implementation?
- Как feature-модули общаются, не зная друг о друге? (навигация через :app, интерфейсы в :domain)
- Минусы? (усложнение Gradle, boilerplate, риск переусложнить)
