Этот способ не всегда применим, ведь не факт, что готовая библиотека может выполнить то преобразование, которое задумано для нового приложения.

Версии Android
Изначально версиям Android присваивались не только номера, но и специальные названия, в алфавитном порядке: Android Marshmallow (6.0 и 6.0.1), Android Oreo (8.0 и 8.1), Android Pie (9.0). Сделано это было для удобства пользователей: во всей этой нумерации версий легко запутаться, а по названиям сладостей было легко отличить существенные выпуски Android друг от друга и (по алфавиту) определить, какая версия вышла раньше, а какая — позже.
Начиная с версии Android 10 компания Google отказалась от такого именования, и теперь каждому крупному обновлению операционной системы соответствует только номер. Впрочем, иногда к номеру добавляется буква, с которой могло бы начинаться название следующей по алфавиту сладости.

Версии SDK cоответствует стабильной версии Android(важно для разработчиков)
Например, Android 9.0 (Pie) → версия SDK 28, Android 13 → версия SDK 33.

Версии API=Версия SDK
В мире Android-разработки вместо упоминания версии SDK можно встретить **уровень API** (API level) с тем же номером, что и у SDK. Технически SDK и API это совершенно разные понятия. 
**SDK** (от английского software development kit) — это набор инструментов для разработки программного обеспечения. В случае с Android SDK это наборы готовых классов, интерфейсов, примеров, документации, вспомогательных программ (таких как ADB) и образов эмуляторов, с помощью которых мы можем создавать мобильные приложения.
**API** (от английского Application Programming Interface) — это технические **правила** взаимодействия программ между собой. Это могут быть публичные методы, набор команд управления или список серверных запросов (в случае, если программа находится на удалённом сервере).
Когда в разговоре об Android-приложении речь идёт об уровне API — имеется в виду набор классов и интерфейсов, входящих в состав SDK. И если, например, говорят о SDK версии 32, то ей соответствует уровень API 32, а когда говорят об уровне API 30, то речь идёт о компонентах, доступных в SDK версии 30.

 Важно!
 Важно быть в курсе последних версий,  ведь каждый раз при создании нового приложения перед нами встаёт задача: нужно выбрать самую старую версию Android, которая будет поддерживаться приложением, иначе говорят — минимальную версию или версию с наименьшим номером. На практике разработчик или разработчица должны указать минимальную версию SDK.
Каждая следующая версия SDK содержит возможности, которых нет в предыдущих версиях, соответственно, и API в SDK поддерживает эти новые возможности. **API — это интерфейс взаимодействия двух программ**, где одна программа — это приложение, а вторая программа — это установленная на смартфоне операционная система Android. И если уровень API устройства (установленная версия Android) ниже минимально допустимой для приложения, то приложение не будет работать на таком устройстве.
Т.е если мы у себя в приложении установили версию min SDK=33(Android 13), а у человека стоит Android 10, то приложение работать не будет.
Чтобы приложение было доступно хотя бы для 80% всех пользователей, на сегодняшний день минимальной поддерживаемой версией SDK должна быть 27 (это Android 8.1 Oreo).

Выбор минимальной версии SDK зависит от двух вещей:
1. **Задачи, которые решает приложение.** Если приложению не нужны возможности новейших версий Android, то можно понизить минимальную версию SDK и тем расширить аудиторию приложения.
2. **Требования заказчика или технического задания.** Бывает так, что минимальная версия Android, указанная в техническом задании, не соответствует требованиям к приложению (заказчик хочет одновременно и охватить аудиторию, и получить функции новейших версий Android). В такой ситуации разработка приложения значительно усложнится, поскольку придётся искать способы реализовать функции имеющимися возможностями.

- Поскольку на уровне системы нет строгих ограничений на используемое оборудование, производитель может устанавливать на смартфон любой процессор, которой дешевле произвести или который можно дороже продать.Низкое качество процессора может привести к тому, что оптимальный по всем параметрам код будет выполняться совершенно неожиданным образом. Частично с этой проблемой помогает справиться ART и официальные JVM спецификации, но и это может привести к неожиданным последствиям.
- При создании приложений работа с нестандартным «железом» может вызвать сложности.
- Производитель может вносить изменение в ключевые сервисы операционной системы: отслеживание фоновых процессов, контроль беспроводных сетей, работа с электропитанием.

Это нередко приводит к тому, что на некоторых устройствах определённые операции будут выполняться не так, как задумано.
- Производители могут вносить изменения в визуальную составляющую операционной системы: чтобы как-то выделиться на фоне конкурентов — они отказываются от стандартной графической оболочки Google Android. Так появляются всевозможные EMUI (визуальная оболочка устройств Huawei), MIUI (Xiaomi), One UI (Samsung) и прочие.

На первый взгляд, это просто декор, ни на что не влияющее оформление — но подмена графической оболочки может создать серьёзные проблемы: стандартные компоненты системы, которые разработчик использует в приложении, на таких устройствах могут выглядеть и работать иначе, чем ожидалось.
