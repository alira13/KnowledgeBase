### 1. **Папка проекта**

На верхнем уровне Android Studio можно увидеть корневую папку проекта, которая имеет несколько подпапок и файлов. В зависимости от представления (Project, Android и т.д.) папки могут выглядеть немного по-разному. Обычно структура выглядит так:

1. AppName. Здесь проходит весь процесс разработки.
  - app - модуль приложения
- **build.gradle (Project)** — файл конфигурации для всей структуры проекта. Здесь настраиваются версии Gradle, подключаются зависимости и плагины, например, `com.android.application`.
- **settings.gradle** — файл, в котором указаны модули проекта (например, `app`, `library`). Также здесь указываются пути к другим модулям, если проект состоит из нескольких модулей.
- **gradle.properties** — хранит свойства Gradle, такие как параметры кэширования или конфигурации для сборки.
- **local.properties** — файл, который обычно не коммитится в систему контроля версий. Здесь прописывается путь к Android SDK и другие настройки, специфичные для локальной среды.
- gitignore

3. External Libraries. Здесь хранятся зависимости проекта, которые используются в процессе разработки. Например, по умолчанию в этой директории можно найти зависимости `androidx` библиотек, которые нужны для построения ui, тестирования и т. д. 
4. Scratches and Consoles используются как заметки разработчика, например, чтобы написать и проверить небольшой метод для проекта.

### 2. **Модуль приложения (обычно `app`)**

Модуль `app` — это главный модуль проекта Android, который содержит код приложения, ресурсы и дополнительные файлы. Внутри `app` находится следующая структура:

#### Основные папки и файлы внутри модуля `app`:

- **src** — основная папка для исходного кода и ресурсов:
    
    - **main** — содержит основной код приложения:
        - **java** — содержит Java или Kotlin-код приложения:
            - Пакеты и классы (например, `MainActivity`, `ViewModel`, `Repository`).
        - **res** — содержит ресурсы:
            - **drawable** — папка для растровых и векторных изображений (иконки, изображения и т.п.).
            - **layout** — XML-файлы для разметки экранов (например, `activity_main.xml`).
            - **values** — папка для XML-файлов, содержащих значения:
                - **colors.xml** — цвета, используемые в приложении.
                - **strings.xml** — строки текста для многоязыковой поддержки.
                - **styles.xml** — стили и темы, применяемые к компонентам.
            - **mipmap** — папка для иконок приложения разных размеров.
    - **test** — содержит юнит-тесты.
    - **androidTest** — содержит тесты для Android-инструментов (интеграционные тесты).
- **build.gradle (Module)** — файл конфигурации для модуля. В нем указываются зависимости, версии SDK, конфигурации для релизной и отладочной сборок.
    

Папка App
Разберёмся, что внутри.

- build.gradle — файл, в котором прописан сценарий сборки модуля.
- proguard-rules.pro — файл, в котором прописаны правила для настройки proguard.

**ProGuard** — это инструмент, который используется в процессе сборки приложения. Главная задача ProGuard — поменять имена объектов, классов, методов, тем самым затрудняя анализ кода для реверс-инженера.

**Реверс-инженер** — это специалист, который исследует готовый проект, чтобы понять принцип работы или найти уязвимости.
### 3. **Gradle Scripts**

В этой папке находятся скрипты, которые управляют сборкой и настройкой проекта:

- **build.gradle (Project)** и **build.gradle (Module)** — основные скрипты сборки.
- **gradle-wrapper.properties** — настраивает Gradle Wrapper, обеспечивая стабильную версию Gradle для проекта.
- **proguard-rules.pro** — файл конфигурации ProGuard для уменьшения и оптимизации кода в релизной версии приложения.

### 4. **Дополнительные папки и файлы**

В проекте могут быть дополнительные папки, такие как:

- **.idea** — конфигурационные файлы среды разработки IntelliJ IDEA и Android Studio. Обычно не нужно вручную изменять файлы в этой папке.
- **build** — папка, создаваемая во время сборки проекта. Содержит временные файлы и артефакты сборки, такие как APK-файлы.
- **libs** — папка для добавления сторонних библиотек вручную в формате `.jar` или `.aar`.

### 5. **Папка с ресурсами `assets`**

Внутри папки `src/main` может быть папка **assets**, в которой хранятся вспомогательные файлы, доступные из кода приложения, например, HTML-файлы, шрифты или базы данных SQLite.

### 6. **Manifest файл**

Файл **AndroidManifest.xml** находится в `src/main` и описывает основные настройки приложения:

- **Основные компоненты** приложения (активности, сервисы, ресиверы).
- **Разрешения** (например, доступ к камере, интернету и т.д.).
- **Настройки метаданных** (иконка, тема, наименование и т.п.).


Обычно ProGuard используют перед сборкой релизной версии приложения. Кроме этого, он оптимизирует код, удаляя неиспользуемые в программе ресурсы.

- В src/androidTest и src/test находятся тесты для проекта. Подробнее про тестирование мы поговорим в следующих спринтах.
- В src/main/java находятся все исходники проекта. Разработчики и разработчицы создают внутри директории структуру проекта в зависимости от архитектуры, которую они используют, и от предметной области приложения. 
- src/main/res — директория ресурсов приложения, в которой хранятся: строки, цвета, стили и размеры.
- src/main/AndroidManifest.xml содержит подробную информацию о приложении. Каждое приложение имеет свой файл AndroidManifest.xml. 

**AndroidManifest.xml** нужен для описания компонент приложения, объявления списка необходимых разрешений для обращения к защищённым частям API и взаимодействия с другими приложениями. Он и объявляет имя Java-пакета приложения, который служит уникальным идентификатором.


Ресурсы приложения
Под ресурсами в Android подразумеваются строки, цвета, стили, размеры, картинки, разметка и прочие атрибуты.

У каждого ресурса есть собственная директория или файл. Рассмотрим основные из них:

- В values/colors.xml находятся цветовые ресурсы.
- В values/strings.xml лежат строковые ресурсы.
- В values/themes.xml — стили.
- В директории layout находятся xml разметки, которые используются в приложении. 
- В drawable лежат графические ресурсы, которые могут быть обычными картинками или xml разметкой.
- В mipmap хранятся адаптивные иконки приложения. В зависимости от плотности пикселей на экране, создаётся несколько вариантов иконки (hdpi, mdpi, xhdpi, xxhdpi, xxxdpi).
