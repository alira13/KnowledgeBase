1. Подключить библиотеку Dagger в gradle и Kotlin Annotation Processing Tool — специальный инструмент, чтобы работать с аннотациями в Kotlin.
2. Добавить аннотацию `@Inject` для конструктора класса, в который внедряем зависимости. Так Dagger понимает, как нужно создавать экземпляр класса и какие у него зависимости (аргументы в конструкторе `RemoteDataSource` и `LocalDataSource`).
3. Но Dagger всё ещё не знает, как создать объекты `RemoteDataSource` и `LocalDataSource`. Для этого нужно добавить `@Inject`-аннотацию и для этих классов:

```Kotlin
class RemoteDataSource @Inject constructor() { ... }
class LocalDataSource @Inject constructor() { ... }
```

После того как мы указали в коде, какие классы зависят от других и как создаются, Dagger создаёт **граф зависимостей** — структуру данных, в которой описано, кто от кого и как зависит. Во время работы приложения каждый раз, когда приложению нужна какая-то зависимость, Dagger будет искать её в этом графе.  
  
4. Dagger умеет создавать несколько графов, и нужно понимать, в каком из них стоит искать нужный класс. Нужно объявить в Dagger компонент.  

Для этого создаётся интерфейс и помечается с помощью аннотации `@Component`. В этом интерфейсе надо определить функции, которые возвращают экземпляры нужных классов (например, `MusicRepository`)

На основе этого интерфейса Dagger создаст класс, в котором будет находиться граф с необходимыми зависимостями.

1. Получаем нужный нам класс

```Kotlin
// Создаётся Dagger-класс, содержащий граф
val applicationGraph: ApplicationGraph = DaggerApplicationGraph.create()
// Ищем нужный класс в графе
val userRepository: MusicRepository = applicationGraph.repository()
```

1. Определяем жизненный цикл

В текущей реализации, каждый раз, при вызове `applicationGraph.repository()`, будет создаваться новый экземпляр класса `MusicRepository`.

Реализовать такой подход поможет аннотация `@Singleton`.

Нужно добавить её к интерфейсу-компоненту, а затем к каждому отдельному классу, который не должен пересоздаваться.
