1.Подключаем зависимости
Это Kotlin Annotation Processing Tool — специальный инструмент, чтобы работать с аннотациями в Kotlin.
2. Определяем точку входа в приложение(создаем пакет app, в нем класс App:Application), добавляем в манифест name = app.App
3. Создаем пакет di. И там классы AppModule, DomainModule, DataModule. Помеяаем их аннотациями @Module
4. Создаем интерфейс AppComponent и помечаем его аннотацией @Component

Аннотация module - представляет зависимости, когда нельзя повесить на конструкторы @Inject. В модулях мы сами создаем компоненты через методы и помечаем из аннотацией provide. А затем подключаем модуль в компоненте

@Binds используется для связывания интерфейсов и их реализаций. Его исползование предпочтительнее, так как тогда не генерится класс для модуля а dagger просто автоматически понимае

Dagger - образовался от абревеатуры. Зависимости представляют собой направленный ацикличный граф, который создает Component/

@Singleton - говорит что пока живет компонент, помеченный этой аннотацией, столько же и будет жить объект созданный в нем и помеченный этой аннотацией, то есть дубликаты создаваться не будут внутри этого времени жизни. getDb будет возвращать.
На практике редко используют @Singleton При взгляде на класс помеченный аннотацией Singleton непонятно, какое у него время жизни, так как мы не видим где создается сам компонент и название нам ни о чем не говорит. Для этого можно создать свою аннотацию AppScope и по названию будет видно, какое время жизни будет у класса. Затем в DataModule можно повесить аннотацию на создание remoteDataSource и localDataSource
