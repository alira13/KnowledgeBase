При запуске приложения Android происходит ряд процессов, которые включают создание и запуск различных компонентов. Вот краткий обзор того, что происходит:

Лаунчер — это системный экран со списком всех приложений, установленных на устройстве.
При нажатии на иконку приложения у нас посылается интент.
Самый простой пример `intent-filter` генерирует среда разработки для первой `Activity` в проекте. 

```
        <activity
            android:name=".MainActivity"
            android:exported="true">
            <intent-filter>
                <action android:name="android.intent.action.MAIN" />

                <category android:name="android.intent.category.LAUNCHER" />
            </intent-filter>
        </activity> 
```

`android.intent.action.MAIN` и `android.intent.category.LAUNCHER` указывают на то, что `MainActivity` — главная точка входа в приложения и может быть запущена из лаунчера приложений. 

## `action MAIN`

- **Описание**: `android.intent.action.MAIN` — это действие, которое указывает на то, что активность является главной точкой входа в приложение. Оно сообщает системе, что эта активность должна быть запущена при старте приложения.
    
- **Роль**: Это действие позволяет системе определить, какую активность запускать первой при запуске приложения.
    
## `category LAUNCHER`

- **Описание**: `android.intent.category.LAUNCHER` — это категория, которая указывает на то, что активность должна быть отображена в списке приложений (лаунчере). Это позволяет пользователю запускать приложение из лаунчера
- **Роль**: Эта категория необходима для того, чтобы активность была доступна из списка приложений и могла быть запущена пользователем.
## Процесс создания контекста

1. **Запуск приложения**: Когда приложение запускается, система создает процесс для приложения и запускает экземпляр класса **Application**.
    
2. **Создание Application Context**: В этот момент создается Application Context, который предоставляет глобальный контекст для приложения.
    
3. **Запуск первой активности**: После этого запускается первая активность, и создается Activity Context для этой активности.

## 🔥 **Как работает системный экран со списком всех приложений в Android?**

Системный экран с **списком всех приложений** в Android — это экран, который отображает все установленные на устройстве приложения. Он обычно называется **"Меню приложений"** (или **App Drawer**), и он реализован с помощью **Intent** и **Content Provider**.

### 1. **Что такое App Drawer?**

App Drawer — это часть интерфейса в Android, которая отображает все приложения, установленные на устройстве. Этот экран обычно можно открыть через иконку на главном экране или через свайп.

---

### 2. **Как Android получает список приложений?**

Android использует **`PackageManager`** для получения информации обо всех установленных приложениях. Этот класс предоставляет методы для запроса информации о приложениях, например, их названиях, иконках и компонентах.

### 3. **Основные шаги, как работает экран с приложениями:**

#### 3.1 **Получение списка установленных приложений через PackageManager**

Чтобы получить список установленных приложений, Android использует `PackageManager`. Пример кода:

```kotlin
val packageManager = context.packageManager
val installedApps = packageManager.getInstalledApplications(PackageManager.GET_META_DATA)
```

Этот метод возвращает список объектов типа `ApplicationInfo`, которые содержат информацию о каждом приложении, установленном на устройстве.

#### 3.2 **Получение информации об иконках и названии приложений**

Для каждого приложения можно запросить **иконку** и **название** с помощью методов `PackageManager`:

```kotlin
for (app in installedApps) {
    val appName = app.loadLabel(packageManager).toString()
    val appIcon = app.loadIcon(packageManager)
    // Используйте appName и appIcon для отображения
}
```

#### 3.3 **Запуск приложений**

Когда пользователь нажимает на иконку приложения в списке, запускается **Intent**, который инициирует запуск соответствующего приложения:

1. **Запуск приложений**:
    - Когда пользователь выбирает приложение из списка, создается Intent с категорией `LAUNCHER`, который запускает основную активность приложения.
    - Это происходит через механизм Intent, который позволяет системе определить, какое приложение должно быть запущено.
2. **Обработка Intent**:
    - Система обрабатывает Intent и запускает соответствующую активность приложения.
    - Если приложение уже запущено, система может либо создать новую задачу, либо использовать существующую в зависимости от настроек приложения.
3. **Управление задачами**:
    - Android управляет задачами (tasks) и стеком активностей, чтобы пользователь мог легко переключаться между приложениями.
    - Каждая задача представляет собой стек активностей, которые можно просматривать в экране недавних приложений.

```kotlin
val intent = packageManager.getLaunchIntentForPackage(packageName)
if (intent != null) {
    startActivity(intent)
}
```

#### 3.4 **Использование `Intent` для фильтрации приложений**

Можно использовать `Intent` для отображения только тех приложений, которые могут обрабатывать конкретный тип данных, например, все приложения, которые могут открывать PDF-файлы:

```kotlin
val intent = Intent(Intent.ACTION_VIEW)
intent.type = "application/pdf"
val activities = packageManager.queryIntentActivities(intent, 0)
```

---

### 4. **Работа с Content Provider:**

Для доступа к данным о приложениях, таким как разрешения, настройки и содержимое, Android использует **`ContentProvider`**. С помощью `ContentProvider` можно извлекать информацию о приложениях из системных баз данных.

Пример использования `ContentProvider` для доступа к информации о контактах или мультимедийных файлах:

```kotlin
val contentResolver = context.contentResolver
val uri = Uri.parse("content://contacts/people/")
val cursor = contentResolver.query(uri, null, null, null, null)
```

---

### 5. **Как это работает на уровне системы?**

- **PackageManager** получает данные о приложениях, зарегистрированных в системе, из **системных файлов** и **базы данных**, хранящихся в `/data/app/` или других директориях устройства.
- **App Drawer** в лаунчерах или системных интерфейсах отображает эти приложения с их иконками и названиями, используя данные, полученные через `PackageManager`.
- Пользователь может **открыть приложение**, нажав на его иконку, что инициирует создание `Intent` для запуска основного компонента приложения.

---

### 6. **Реализация в вашем приложении (если хотите создать свой экран со списком приложений)**

#### Пример кода для отображения списка всех установленных приложений:

```kotlin
class AppListActivity : AppCompatActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContentView(R.layout.activity_app_list)

        val packageManager = packageManager
        val installedApps = packageManager.getInstalledApplications(PackageManager.GET_META_DATA)

        val appListAdapter = AppListAdapter(installedApps)
        val listView: ListView = findViewById(R.id.appListView)
        listView.adapter = appListAdapter
    }
}
```

### 7. **Использование системных лаунчеров**

Системный экран с приложениями отображается с помощью стандартных **лаунчеров** (например, Google Pixel Launcher). Однако, вы также можете создать свой собственный лаунчер, используя `PackageManager` для получения всех установленных приложений и их отображения.

### 8. **Доступ к системным приложениям и разрешениям**

При использовании `PackageManager` вы можете получить информацию о приложениях, включая те, которые скрыты или системные. Чтобы фильтровать такие приложения, можно использовать `getInstalledPackages()`:

```kotlin
val installedPackages = packageManager.getInstalledPackages(PackageManager.GET_PERMISSIONS)
```

## 1. Создание процесса приложения

- **Форк от Zygote**: Каждое приложение запускается в отдельном процессе, который создается путем форка (разделения) от процесса **Zygote**. Это позволяет экономить память и ускорять запуск приложений, поскольку Zygote уже загрузил многие системные библиотеки и ресурсы[5](https://habr.com/ru/articles/521522/).

## 2. Запуск ActivityThread

- **ActivityThread**: После создания процесса запускается класс **ActivityThread**, который является основным потоком приложения. Он отвечает за обработку сообщений и выполнение действий, таких как запуск активностей[2](https://habr.com/ru/articles/345120/).

## 3. Создание и запуск активностей

- **MainActivity**: Первой запускается **MainActivity**, которая является входной точкой приложения. Она создается и запускается через **ActivityThread**[2](https://habr.com/ru/articles/345120/).
- **Жизненный цикл активности**: После создания активности проходит через различные стадии своего жизненного цикла, такие как `onCreate()`, `onStart()`, `onResume()`[8](https://metanit.com/java/android/2.1.php).

## 4. Запуск служб и широковещательных приемников

- **Службы (Services)**: Если приложение использует службы, они запускаются отдельно и могут выполнять задачи в фоновом режиме.
- **Широковещательные приемники (BroadcastReceivers)**: Эти компоненты могут получать и обрабатывать широковещательные сообщения, отправленные системой или другими приложениями[4](https://vladislaveremeev.gitbook.io/qa_bible/mobilnoe-testirovanie/android/arkhitektura-android-application).

## 5. Создание и запуск других компонентов

- **Фрагменты и другие компоненты**: В зависимости от архитектуры приложения могут создаваться и запускаться фрагменты, адаптеры и другие компоненты, необходимые для работы приложения.

## 6. Обработка Intent

- **Intent**: При запуске приложения может передаваться Intent, который указывает на конкретное действие или активность, которую необходимо запустить. Система обрабатывает этот Intent и запускает соответствующий компонент[4](https://vladislaveremeev.gitbook.io/qa_bible/mobilnoe-testirovanie/android/arkhitektura-android-application).

Эти процессы обеспечивают запуск и работу приложения Android, позволяя ему взаимодействовать с системой и другими приложениями.
