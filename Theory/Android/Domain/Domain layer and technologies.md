### **Слой Domain в Чистой Архитектуре**

Слой **Domain** в **Clean Architecture** отвечает за **бизнес-логику** приложения. Он не зависит от UI, базы данных или сетевых сервисов. Основная цель этого слоя — хранить **чистую логику**, которая может быть легко протестирована и не зависит от Android-фреймворка.

---

### **Основные компоненты слоя Domain**

1. **Use Case (Interactor)**
    
    - Инкапсулирует бизнес-логику.
    - Получает данные от репозитория и выполняет операции.
    - Не знает, откуда приходят данные (из сети или базы данных).
    
    🔹 **Пример Use Case**
    
    ```kotlin
    class GetUserUseCase(private val userRepository: UserRepository) {
        suspend fun execute(userId: Int): User {
            return userRepository.getUserById(userId)
        }
    }
    ```
    
2. **Entities (Модели бизнес-логики)**
    
    - Простые классы `data class`, описывающие бизнес-данные.
    - Они **не** содержат аннотаций (`@Entity`, `@SerializedName`).
    
    🔹 **Пример Entity**
    
    ```kotlin
    data class User(val id: Int, val name: String, val email: String)
    ```
    
3. **Repository Interface**
    
    - Интерфейс, который определяет, **какие** данные нужны.
    - Не содержит реализации, только методы.
    - Реализация этого интерфейса находится в **Data-слое**.
    
    🔹 **Пример интерфейса**
    
    ```kotlin
    interface UserRepository {
        suspend fun getUserById(id: Int): User
    }
    ```
---

### **Какие технологии и библиотеки можно использовать в Domain-слое?**

Поскольку Domain-слой **не должен зависеть от фреймворка Android**, здесь **используются только чистые Kotlin-библиотеки**:

|Библиотека/Технология|Описание|
|---|---|
|**Kotlin Coroutines** (`Flow`)|Асинхронная обработка данных|
|**RxJava**|Альтернативный способ обработки потоков данных|
|**Kotlin Result**|Обертка для обработки ошибок (`Result<T>`)|
|**Arrow**|Функциональное программирование в Kotlin|

---

### **Пример Domain-слоя с Kotlin Flow**

Допустим, у нас есть репозиторий, который возвращает поток (`Flow`) пользователей.

```kotlin
class GetUsersUseCase(private val userRepository: UserRepository) {
    fun execute(): Flow<List<User>> {
        return userRepository.getUsers()
    }
}
```

Это удобно, потому что: ✅ **Отсутствие зависимостей от Android** → Код легко тестировать  
✅ **Flow поддерживает асинхронность** → Не блокирует поток  
✅ **Можно легко менять источник данных** → Например, заменять сеть на кэш

---

### **Итог**

Слой **Domain** — это сердце приложения, где хранятся бизнес-правила. Он **не должен** зависеть от Android SDK или конкретных технологий.

📌 **Главные принципы:**  
✅ Только **чистый Kotlin-код**  
✅ Работа с **интерфейсами репозиториев**, но без их реализации  
✅ Использование **Use Case** для обработки логики  
✅ **Flow / Coroutines** для асинхронности

В результате Domain-слой остается **независимым**, что упрощает тестирование и поддержку. 🚀
