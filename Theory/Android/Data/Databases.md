### 🔹 1.1 **Реляционные базы данных (SQL)**
### Реляционные базы данных(SQL) - чаще всего используются в Android

Реляционные базы данных — наиболее распространённый тип, который используется в большинстве приложений. В таких БД информация хранится в форме **таблиц**, а данные между таблицами могут быть связаны посредством ключей.  
С помощью ключей можно выстраивать отношения между таблицами. Отсюда и название «реляционные»: в переводе с английского relations — «отношения»  

![](<images/Untitled 3.png>)

Реляционные базы данных называют **SQL-базами** из-за специального языка для запросов к базе данных SQL — Structured Query Language.  
С помощью SQL описывают манипуляции над таблицами: создать, вставить или обновить данные, удалить отдельные строки таблиц и, главное,  
**запросить данные**— осуществить поиск.

📌 Данные хранятся в **таблицах** (как в Excel).  
📌 Используют **SQL (Structured Query Language)** для запросов. Отсюда и название
📌 Все данные **структурированы**, есть чёткие связи (отношения).

**Популярные SQL базы:**

- **PostgreSQL** – надёжная, бесплатная, расширяемая.
- **MySQL** – простая, популярная, часто используется с сайтами.
- **SQLite** – лёгкая, встроенная в Android (используется в Room).
- **Microsoft SQL Server** – мощная, используется в крупных компаниях.

✅ **Когда использовать SQL БД?**  
✔ Если данные строго структурированы.  
✔ Если нужны сложные связи между объектами.  
✔ Если важна целостность данных.

📌 **Пример SQL-запроса:**

```sql
SELECT * FROM users WHERE age > 18;
```

### 🔹 1.2 **NoSQL базы данных**

📌 Данные хранятся не в таблицах, а в **документах, ключах-значениях, графах или столбцах**.  
📌 Подходят для **гибких, масштабируемых приложений**.  
📌 Не требуют строгой структуры.

**Популярные NoSQL базы:**

- **MongoDB** – хранит данные в JSON-документах.
- **Redis** – сверхбыстрое хранилище ключ-значение.
- **Firebase Firestore** – облачная база от Google для мобильных приложений.
- **Cassandra** – распределённая база данных от Facebook.

✅ **Когда использовать NoSQL?**  
✔ Данные меняются динамически.  
✔ Нет сложных связей между объектами.  
✔ Нужна высокая скорость и масштабируемость.

📌 **Пример JSON-документа в MongoDB:**

```json
{
  "id": 1,
  "name": "Иван",
  "email": "ivan@example.com"
}
```

---
### Базы данных NoSQL

**Базы данных NoSQL (not only SQL, или нереляционные)** — это общее название для баз данных, которые не соответствуют модели реляционных баз данных. БД NoSQL могут быть организованы по-разному:

- **Документоориентированные БД** используют структуры типа «ключ — значение», где значениями будут JSON-объекты. Это позволяет хранить в базе неструктурированные и неоднородные данные.
- В **колоночных БД** данные разделены не по строкам, а по столбцам. Это сильно ускоряет операции чтения, которые нацелены только на несколько свойств одного объекта, а не на все разом. В основном это требуется для анализа систем с очень большим объёмом данных (например, хранилища в 300–500 Тб и больше).
- **Графовые БД** позволяют хранить связи между сущностями в виде графов. Этот тип базы данных идеален для случаев, когда нужно эффективно представлять и обрабатывать сложные взаимосвязи, например, в социальных сетях или системах рекомендаций.
## 📌 **2. Локальные базы данных в Android**

В Android можно хранить данные **на устройстве пользователя**, без сервера.

### 🔹 2.1 **SQLite**

✔ Встроенная база в Android.  
✔ Данные хранятся в файле `.db`.  
✔ Используется в **Room (Android Jetpack)**.

📌 **Пример создания таблицы в SQLite:**

```sql
CREATE TABLE users (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT,
    age INTEGER
);
```

**Как работать с SQLite в Android?**

- **Чистый SQLite** – через `SQLiteOpenHelper`.
- **Room** (лучше!) – более удобный слой над SQLite.

📌 **Пример работы с Room в Android:**

```kotlin
@Entity
data class User(
    @PrimaryKey val id: Int,
    val name: String
)

@Dao
interface UserDao {
    @Query("SELECT * FROM users")
    fun getUsers(): List<User>
}
```
