

1. **Имя проекта (Project Name)**:
    - Используйте **CamelCase** (например, `MyFirstApp`) для записи имени проекта.
    - Избегайте пробелов, специальных символов и цифр в начале имени.
    - Имя проекта должно быть **коротким, но информативным**, чтобы отражать его назначение.
    - Рекомендуется начинать с **основного слова**, описывающего функционал или суть проекта, например, `WeatherApp`, `TaskManager`.
2. **Название пакета (Package Name)**:
    - Название пакета служит уникальным идентификатором приложения и используется в Google Play. Оно должно соответствовать стандарту Java для именования пакетов.
    - Используйте формат **обратного доменного имени**: `com.companyname.appname` (например, `com.example.weatherapp`).
    - Название пакета обычно состоит из трех частей:
        - **Домен**: В начале используется домен вашей компании или вашего проекта, например, `com` или `org`.
        - **Название компании/проекта**: Добавьте уникальный идентификатор компании или проекта, например, `example`.
        - **Название приложения**: Последняя часть представляет собой имя самого приложения, например, `weatherapp`.
    - Используйте **только строчные буквы** и избегайте специальных символов и цифр в начале.
3. **Имена классов и файлов**:
    - Классы именуются в **CamelCase**, обычно с большой буквы, например, `MainActivity`, `UserProfile`.
    - Классы и файлы должны четко указывать на свою роль и предназначение.
    - Избегайте слишком длинных имен, чтобы сохранить код удобочитаемым.
4. **Имена ресурсов** (изображения, строки, цвета и т. д.):
    - Имена ресурсов должны быть **в нижнем регистре** и разделены подчеркиванием (`_`), например, `ic_launcher`, `background_color`.
    - Для иконок добавляется префикс ic
    - Выбирайте **конкретные и описательные имена**, чтобы можно было легко понять, что это за ресурс.
    - Для именования цветов и строк, используйте **префиксы** для группировки:
        - Цвета: `color_primary`, `color_accent`.
        - Строки: `str_app_name`, `str_welcome_message`.
5. **ID элементов интерфейса** (View IDs):
    - Используйте **формат нижнего регистра с подчеркиванием**, например, `btn_login`, `tv_username`.
    - Префиксы по типу виджета помогают сразу понять, к какому элементу относится данный ID:
        - Кнопки: `btn_` (например, `btn_submit`).
        - Текстовые поля: `tv_` для `TextView` (например, `tv_title`).
        - Поля ввода текста: `et_` для `EditText` (например, `et_email`).
        - Изображения: `img_` (например, `img_logo`)
		- ProgressBar - pb
		- Checkbox - chk
		- RadioButton - rb
		- ToggleButton - tb
		- Spinner - spn
		- Menu - mnu
		- ListView - lv
		- GalleryView - gv
		- LinearLayout -ll
		- RelativeLayout - rl

1. **Имена модулей**:
    - В Android Studio можно разделить проект на модули. Имя модуля должно быть **коротким и описательным**, отражая его назначение, например, `app`, `network`, `authentication`.
    - Используйте **строчные буквы без пробелов** (если нужно разделить слова, используйте подчеркивание).
2. **Имя Gradle-задач**:
    - Название задачи в Gradle должно быть **коротким и четким** и отражать назначение задачи.
    - Пример именования задач: `assembleDebug`, `cleanBuild`.
3. Имена пакетов внутри приложения
	- должны содержать 1 слова с маленькой буквы
	- если не получается с 1м словом, тогда с camelCase 



### **Именование ресурсов**
#### 1. **Именование строковых ресурсов**

При работе с текстовыми ресурсами в Android важно использовать **понятные и структурированные имена строковых ресурсов** в `strings.xml`. Это улучшает читаемость и поддержку кода, особенно когда проект растет.

Вот несколько рекомендаций и правил именования строковых ресурсов:

###### 1. **Используйте префиксы для указания типа строки**

Разделяйте строки на группы по их назначению. Например:
- **`title_`** — для заголовков.
- **`msg_`** — для сообщений.
- **`hint_`** — для подсказок в текстовых полях.
- **`btn_`** — для текста на кнопках.
- **`lbl_`** — для меток и подписей.
- **`desc_`** — для описаний или `contentDescription`.

**Пример**:
```xml
<string name="title_main_screen">Главный экран</string>
<string name="msg_no_connection">Нет соединения с интернетом</string>
<string name="hint_enter_name">Введите ваше имя</string>
<string name="btn_submit">Отправить</string>
<string name="lbl_username">Имя пользователя</string>
<string name="desc_profile_picture">Аватар профиля</string>
```

###### 2. **Используйте область назначения в названии**

Если строка используется только в одном экране или фрагменте, добавьте название этого экрана в имя ресурса. Это облегчает поиск нужных строк.

**Пример**:
```xml
<string name="login_hint_email">Введите вашу почту</string>
<string name="login_btn_sign_in">Войти</string>
<string name="profile_lbl_username">Имя пользователя</string>
<string name="profile_desc_edit_button">Редактировать профиль</string>
```

###### 3. **Именуйте строки в нижнем регистре и через подчеркивания**

Android требует, чтобы имена ресурсов были в **нижнем регистре** и слова разделялись **подчеркиваниями** (`snake_case`).

**Пример**:
```xml
<string name="main_screen_welcome_text">Добро пожаловать</string>
<string name="profile_edit_button_text">Редактировать профиль</string>
```

### 4. **Будьте максимально описательными**

Имена строк должны описывать назначение текста, а не его содержание. Например, вместо `welcome_text` лучше использовать `main_screen_welcome_text`, так как это описывает место назначения строки.

###### 5. **Избегайте прямого указания языка в имени**

Не добавляйте языковые суффиксы в название строк (например, `_en`, `_ru`). Android автоматически использует локализацию на основе ресурсов `values` (например, `values-ru` для русского).

###### 6. **Не используйте цифры и сокращения без необходимости**

Избегайте чисел и аббревиатур в названиях строк, так как они могут быть неочевидными для других разработчиков.

**Плохо**:
```xml
<string name="btn_1">Отправить</string>
<string name="msg_con">Подключение установлено</string>
```

**Хорошо**:
```xml
<string name="btn_submit">Отправить</string>
<string name="msg_connection_successful">Подключение установлено</string>
```

### 7. **Именуйте строки на основе их роли, а не значения**

Название ресурса должно описывать, где и как используется строка, а не её конкретное значение.

**Пример**:
```xml
<string name="error_network_unavailable">Нет подключения к сети</string>
<string name="success_profile_updated">Профиль обновлен успешно</string>
```

###### 8. **Единый стиль для всех ресурсов в проекте**

Все члены команды должны следовать единым правилам. Это предотвратит путаницу и улучшит поддержку проекта.

### Итоговый пример структуры `strings.xml`

```xml
<resources>
    <!-- Заголовки -->
    <string name="title_settings_screen">Настройки</string>
    <string name="title_profile_screen">Профиль</string>

    <!-- Подсказки -->
    <string name="hint_search">Введите текст для поиска</string>

    <!-- Тексты кнопок -->
    <string name="btn_save">Сохранить</string>
    <string name="btn_cancel">Отмена</string>

    <!-- Сообщения об ошибках -->
    <string name="error_network_unavailable">Нет подключения к сети</string>
    <string name="error_invalid_email">Некорректный адрес электронной почты</string>
</resources>
```

Эти правила помогут вам поддерживать порядок в строковых ресурсах и упростят локализацию приложения.
