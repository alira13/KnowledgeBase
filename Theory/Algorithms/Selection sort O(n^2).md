# Сортировка выбором — O(n²)

**Сортировка выбором (selection sort)** — учебный алгоритм: на каждом шаге находим минимум среди неотсортированной части и ставим его на своё место.

## Принцип
Массив мысленно делится на две части: слева — уже отсортированная, справа — оставшаяся.
1. Найти минимум в неотсортированной части.
2. Поменять его местами с первым элементом этой части.
3. Граница сдвигается вправо на один; повторять, пока не останется один элемент.

```
[5, 3, 8, 1]  → минимум 1, меняем с 5
[1, 3, 8, 5]  → минимум из (3,8,5) = 3, уже на месте
[1, 3, 8, 5]  → минимум из (8,5) = 5, меняем с 8
[1, 3, 5, 8]  → готово
```

```kotlin
fun selectionSort(arr: IntArray) {
    for (i in 0 until arr.size - 1) {
        var minIndex = i
        for (j in i + 1 until arr.size) {      // ищем минимум в остатке
            if (arr[j] < arr[minIndex]) minIndex = j
        }
        if (minIndex != i) {                    // обмен на своё место
            val tmp = arr[i]; arr[i] = arr[minIndex]; arr[minIndex] = tmp
        }
    }
}
```
Обмен «на месте» лучше, чем перекладывание в новый массив: не нужна дополнительная память и нет удаления из середины исходного (которое само по себе стоило бы O(n)).

## Почему O(n²)
На первом проходе делаем n−1 сравнение, на втором n−2, и так далее:

(n−1) + (n−2) + … + 1 = **n(n−1)/2 ≈ n²/2**

Константу 1/2 отбрасываем — остаётся **O(n²)**. Это та самая «треугольная» сумма:

| Характеристика | Значение |
| --- | --- |
| Время (лучший / средний / худший) | O(n²) во **всех** случаях |
| Память | O(1) — сортировка на месте |
| Число обменов | **O(n)** — ровно по одному на проход |
| Устойчивость (stable) | нет (в классической версии с обменом) |
| Адаптивность | нет: на уже отсортированном массиве всё равно O(n²) |

Особенность, за которую его иногда вспоминают: **минимальное число обменов**. Если запись дорогая (флеш-память, большие объекты), а сравнения дёшевы, селекция выигрывает у пузырьковой сортировки, хотя сравнений у них поровну.

**Неустойчивость** легко показать: `[2a, 2b, 1]` → после обмена 1 и 2a порядок одинаковых двоек меняется на `[1, 2b, 2a]`.

## Сравнение с соседями
| Алгоритм | Время | Память | Устойчив | Адаптивен |
| --- | --- | --- | --- | --- |
| **Selection** | O(n²) всегда | O(1) | нет | нет |
| **Bubble** | O(n²), O(n) на отсортированном (с флагом) | O(1) | да | да |
| **Insertion** | O(n²), O(n) на почти отсортированном | O(1) | да | **да** |
| **Merge** | O(n log n) | O(n) | да | нет |
| **Quick** | O(n log n) в среднем, O(n²) в худшем | O(log n) | нет | нет |

Из квадратичных на практике полезна **сортировка вставками**: на почти упорядоченных данных она близка к O(n), поэтому используется как часть гибридных алгоритмов (Timsort в Java/Kotlin переключается на неё для коротких участков). См. [[Sorting algorithms used]].

## Когда применять
Честный ответ — **в продакшене почти никогда**: `list.sorted()` вызывает Timsort с O(n log n). Селекция полезна как учебный пример и в редком случае «крайне дорогая запись, крошечный массив».

## Вопросы-ловушки
- Ускорится ли сортировка выбором на уже отсортированном массиве? → нет, минимум всё равно ищется полным проходом: O(n²) при любых входных данных.
- Сколько обменов делает алгоритм? → не больше n−1 — это его единственное преимущество.
- Устойчива ли она? → нет; вариант со вставкой вместо обмена устойчив, но тогда теряется O(1) по памяти.
- Чем она хуже сортировки вставками? → та адаптивна и устойчива при той же асимптотике.
