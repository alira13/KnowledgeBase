возможности git

- хранение полной истории изменений - хранение списока всех коммитов, сделанных в репозитории. История нужна для отслеживания изменений в коде, понимания причин этих изменений и возможности возврата к более ранним версиям кода.

- ветвление изменений - процесс создания копии основного кода для работы над новой задачей или функциональностью, не затрагивая основной код.

- слияние изменений - все изменения из одной ветки переносятся в другую, возможно с  
решением конфликтов когда нужно перенести свои изменения в основной код проекта. Для этого он использует операцию merge (мёрдж, с англ. —слияние, объединение), и с её помощью объединяет свою ветку с основной веткой проекта.  

merge - это процесс, в котором две или более веток объединяются с основной веткой  
проекта. В большинстве проектов основная ветка называется (в старых  
проектах встречается название ), и она создается автоматически при  
инициализации репозитория  

конфликт - ситуация, когда во время слияния веток Git обнаруживает изменения в  
одних и тех же строках одинаковых файлов в разных ветках. Возникает,  
когда два человека вносят изменения в одни и те же части кода.  

Разрешение конфликтов

Процесс исправления называется решением merge-конфликтов (на англ. — resolve  
merge conflicts). Внесенные в ходе решения конфликта изменения автоматически  
записываются в специальный коммит и сохраняются в истории.  

  

CI/CD

Командная работа с Git неразрывно связана с понятиями непрерывной интеграции  
(Continuous Integration) и непрерывной доставки (Continuous delivery), или  
сокращённо CI/CD. В рамках Android-разработки эти понятия относятся к  
автоматизации сборки, тестирования и выкладки мобильных приложений в  
различные сторы  

Непрерывная интеграция

Continuous Integration (CI) — это практика разработки программного обеспечения,  
которая требует от разработчиков регулярного объединения их изменений в  
основную ветку, как правило, несколько раз в день. Каждое такое объединение  
подвергается автоматизированному процессу тестирования и сборки, чтобы быстро  
обнаруживать любые ошибки или проблемы совместимости.  

Цель CI — уменьшить время и усилия, необходимые для интеграции изменений, а  
также ускорить обнаружение и исправление ошибок. Это помогает командам  
разработки сохранять высокий темп работы и уверенность в том, что любые  
внесенные изменения не нарушат существующую функциональность.  
Примером реализации принципа CI в разработке Android-приложений может служить  
автоматический старт сборки приложения при создании нового pull request в вашем  
репозитории. Сборка может проверить отсутствие ошибок компиляции, прогнать  
ваши тесты, чтобы убедиться, что ваши изменения не сломали уже написанное  
приложение.  

  

Continuous delivery (CD) — это естественное продолжение CI, представляющее  
собой подход, при котором команды разработки стремятся автоматизировать как  
можно больше этапов отправки кодовой базы в production, чтобы новые версии  
приложений могли быть легко и быстро доставлены клиентам.  
В системе непрерывной доставки любые изменения в коде, которые прошли  
автоматическое тестирование, считаются готовыми к безопасной и быстрой отправке  
в production.  
Примером реализации принципа CD в разработке Android-приложений может  
служить настройка отправки собранной и протестированной релизной версии  
приложения напрямую в Google Play.  

  

  

Методологии работы с git

Каждый по отдельности может использовать любые возможности Git, однако для  
эффективной командной работы необходимо договориться об использовании  
определённой методологии. По сути, это набор правил, которые команда согласилась  
соблюдать во время работы над общим проектом.  

Какие именно ветки должны поддерживаться в процессе разработки.  
Когда их следует создавать и удалять.  
Как должны быть организованы процессы слияния и ветвления.
